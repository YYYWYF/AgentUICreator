# Agent 驱动的动态界面

本页于 2026 年 11 月 6 日使用当前 Creator 和 `deepseek-v4.1-flash`，在招行 AI 工作台中重新执行。本轮已接通由 Agent 事件显示、由用户手动提交查询的工单筛选表单。

## 本次怎么说

> 助手收到工单筛选数据时，显示关键词、状态和“查询”按钮。空关键词可以查询全部，只有用户提交时才调用已有工单查询服务。支持等待、取消、空结果和失败重试；结果可以选中工单、打开现有详情。无效数据给业务提示，切换中英文保留输入，新建或重开会话不要自动查询、不要自动发送聊天。直接实施并校验，保持左侧聊天、右侧会话列表和其他助理不变。

这次提供了已有查询、选择和详情接口，以及实际可回放的数据。正常的 AG-UI 事件为：

```json
{
  "type": "CUSTOM",
  "name": "app.ticket.filter",
  "value": {
    "formId": "ticket-filter-1",
    "keyword": "",
    "status": "all",
    "statuses": ["all", "pending", "processing", "resolved"]
  }
}
```

`all` 表示全部状态，其余分别对应待受理、处理中、已完成。已有服务接受关键词、状态和取消信号，返回工单数组；本轮使用工作台中的虚构数据，不连接银行业务系统。

## Creator 实际怎样处理

确认具体新增方案后，Creator 创建项目自有的消息界面插件，补齐数据校验、共享双语文案、查询逻辑和局部样式，再接入事件 schema、注册并启用插件。没有接管官方源码。

完整实现曾因单次模型输出达到上限而中断，因此拆成数轮小步写入。浏览器又发现“选中工单”触发业务页面更新后会重置表单；随后由 Creator 稳定应用层事件 schema 的合并引用，并复测输入和结果保留。最终类型检查、构建和装配校验通过。

## 收到事件后显示表单

实际回放正常事件后，消息中出现筛选表单。此时本地查询记录仍为 0；显示表单本身没有调用查询服务：

![收到 CUSTOM 事件后的初始表单，尚未查询。](/images/guide/examples/20261106/dynamic-initial.jpg)

输入“手机”、选择“处理中”并点击“查询”，实际只得到 `FW-20261022-002`。点击“选中工单”后，上方当前工单同步更新，表单条件与结果仍保留：

![组合筛选及选中工单后的实际页面。](/images/guide/examples/20261106/dynamic-filtered.jpg)

点击结果中的“查看详情”，打开已有的同一工单详情抽屉；关闭详情后，表单结果仍保留：

![从表单结果打开现有业务详情。](/images/guide/examples/20261106/dynamic-details.jpg)

空关键词配合“全部状态”实际返回全部 6 张演示工单。切换英文时，关键词“手机”、状态 `processing` 和原查询结果保持不变，界面状态与操作使用对应英文：

![切换英文后保留输入与查询结果。](/images/guide/examples/20261106/dynamic-english.jpg)

## 空结果、失败、重试与取消

不存在的关键词显示“没有符合当前筛选条件的工单”：

![实际空结果提示。](/images/guide/examples/20261106/dynamic-empty.jpg)

![实际业务失败和重试入口。](/images/guide/examples/20261106/dynamic-error.jpg)

## 无效数据与历史检查范围

将事件状态改为不支持的值，实际显示业务错误，不显示可提交表单；本地查询记录保持 9 次，没有增加。英文也显示对应提示：

![无效状态数据的实际业务提示。](/images/guide/examples/20261106/dynamic-invalid.jpg)

在慢速查询进行中实际新建会话，新会话没有旧表单或结果。再打开原会话时，表单按原事件的初始值显示，未自动恢复查询；这次新建及重开前后，Agent 请求数为 `9 → 9`，本地查询数为 `9 → 9`。

![重新打开原会话，表单等待用户手动查询。](/images/guide/examples/20261106/dynamic-history.jpg)

这里验收的是同一次页面挂载内的会话切换。表单手动查询的结果没有作为新的 Agent 消息保存；本轮也未验收跨刷新历史持久化。接入自己的历史服务后，还需检查实际保存和读取，见[对接会话历史接口](/development/history-backend.md)。

需要自己接入事件和渲染器时，见[自定义 AG-UI 事件与消息渲染](/development/custom-ag-ui-events.md)。
