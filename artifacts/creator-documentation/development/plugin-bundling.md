# 插件按需打包

`@za38.03/agent-ui-plugins` 支持按需打包。一个 npm 包提供多种插件，应用只需选择需要的功能；未启用、也没有被其他代码引用的插件实现，不会进入最终生产产物。

安装包中包含全部插件资源，因此 `node_modules` 的大小不代表最终部署体积。新工程只为配置中使用的插件生成项目入口；已生成或定制的文件在禁用后会保留，不会自动删除。

## 按功能使用公开入口

开发或定制插件时，在实际使用它的文件中，从对应插件的公开子入口导入所需组件。例如，输入区和复制按钮分别使用：

```ts
import { ConversationComposerPlugin } from '@za38.03/agent-ui-plugins/composer';
import { ConversationCopyActionPlugin } from '@za38.03/agent-ui-plugins/copy-action';
```

这些导入不会自动启用插件。新增功能仍需完成项目中的插件配置与注册，步骤见[创建自定义插件](/development/create-plugin.md)。修改已有插件时，优先沿用项目入口中的导入和组件组合。

公共 Hook 和通用展示组件继续按各自文档，从根入口具名导入；类型使用 `import type`：

```ts
import { usePluginService } from '@za38.03/agent-ui-plugins';
import type { UIPluginDefinition } from '@za38.03/agent-ui-plugins/contracts';
```

根入口的具名导入同样支持按需打包，无需把现有公共 API 导入全部改成子入口。各插件可用的组件、类型和入口以对应[插件页面](/plugins/index.md)及项目已安装版本为准。

## 保持按需打包效果

- **只导入实际使用的功能。** 避免在全局入口批量导入、注册全部插件，或通过整包对象动态查找插件。
- **让引用与功能一起启停。** 如果业务页面或另一个已启用插件直接使用某个组件，该组件仍会作为依赖参与构建。跨插件只需调用服务时，使用公开服务接口，避免连带引入提供方的界面实现。
- **沿用生成工程的基础样式入口。** 新工程使用 `@za38.03/agent-ui-plugins/styles-base.css`，插件样式随相应入口引入。`styles.css` 是完整样式入口，会引入更广的样式范围；不要为了添加一个插件而无意中同时加载完整样式。直接复用公共展示组件时，按对应文档选择样式。
- **修改启用配置后同步注册并重新构建。** 可让 Creator 完成启停；手动修改时，按[插件注册与验证](/development/create-plugin.md#4-插件注册与验证)更新，再使用工程已有的构建命令生成生产产物。暂时隐藏组件或尚未收到数据，不等于禁用插件。

共享组件和公共样式可能同时被多个功能使用，禁用一个插件后仍会保留。因此，按需打包会排除不再需要的实现，但不保证每次禁用插件都会明显减小产物。
