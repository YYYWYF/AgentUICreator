# Creator 调查收敛修复与 Windows 复测

本轮按任务进度日志分析实施通用修复，未手工编写测试场景的插件实现。真实模型仍为 deepseek-v4.1-flash，Agent 输出预算 16384、总上下文估算预算 65536、单请求超时 120 秒；模型凭据仍只在本地工具 Host 配置。没有新增累计模型调用、工具调用或图步数上限。

## 实际修改

- 统一官方与项目业务文案的边界：官方键使用既有 namespace / Agent.locales；项目业务键集中在项目共享、按领域组织的双语消息模块，通过统一 locale code 选择，组件消费消息，不创建每插件 i18n Hook、语言条件或独立状态。不新增 Runtime API，不修改 vendor。
- 事件说明区分具名消息渲染与实时应用事件订阅；保留用户给定协议，不冒充标准 ACTIVITY/Tool/Run 语义。Schema 文件按实际 sourceRoot 组织，缺少 agent-contract 目录是可新增的项目代码，不是 Runtime 不支持的证据。文档补充单组件订阅、按业务 ID 合并与取消订阅的例子。
- 归档页是原工具观察的再次展示，不再计作新证据。同一修订持续调查会收到说明具体缺口/冲突的提醒，允许继续必要研究或做可撤销实现；只读任务明确保持只读，不强制修改、不停止长任务。
- 共享 API 查询省去无关插件清单；所有权仍在 Host 内记录，查询不切换编辑目标。按预算保留实际读到的签名、模块与版本；新版本或查询结果失效会清理旧记录，明确不能从类型推断运行行为。
- 当前 Host 工作上下文按预算保留批准身份及简短实施合同。摘要区分用户、系统、技能、文档、源码观察，保留冲突，目标缩短到 600 词以内，避免重复工具历史/hash。独立摘要输出预算默认 8192、不超过 Agent 输出预算；压缩后为工具往返留出空间，保留完整工具配对、原始 checkpoint 和近期必要续接数据。
- 实测额外暴露的分类问题：JSON Schema 被服务拒绝后，JSON object 降级提示没有完整字段定义。现在两种请求都携带同一完整输出契约，继续严格本地校验；失败日志记录 JSON/外层字段/删除目标哪个阶段失败和字段类型，不保存私有推理或响应正文。
- 实测额外暴露的注册导航问题：创建结果原先只有文件列表，模型长时间寻找不存在的注册表生成脚本。创建结果现说明源码已创建、注册待验证、组合未改变，并指向既有 validate_creator_changes；工具/技能明确此工具会先同步注册表再检查。仍由正常 AppUIModel 工具执行组合，没有隐式挂载。

### 完成结果与 262144 对照

服务 /models 元数据明确声明当前模型 context=1000000、output=384000（model-metadata.json）。据此只增大上下文到 262144 加跑两项对照，其他模型、输出、请求超时及输入保持不变；本地工具配置已保存此上下文预算，凭据仍忽略。
