# Creator 工程修复与原任务复测（2026-11-04）

工程回归通过；真实模型执行原复杂任务仍失败。两轮复测均在 20 分钟观察窗口结束时停止，写入尝试和改动文件都是 0。

## 已完成的修复

1. 工作源码优先保留目标组件与已知本地依赖；CSS 不再抢占自定义插件的首要源码位置。同版本的小范围重读保留已经读取的完整缓存，实际写入仍检查当前内容 hash 和读取范围。
2. inspect_ui_plugin 的共享类型查询只更新引用与归属事实，不切换编辑对象。重新检查同一目标时保留已经解析的组件文件闭包；显式检查另一个编辑目标仍然可用。
3. 文档索引按具体 API 标识符、代码中的标识符和词项区分度排序；章节按自身正文匹配，避免父章节囊括全部子章节而挤掉答案。编辑查询不再混入自定义插件 ID 的名称碎片。
4. 编辑上下文删除“新行为必须使用已确认开发计划”的遗留文字。
5. 第一轮暴露出确认后的工具衔接缺口后，补充：同意新插件开发后自动显示 plugin_authoring 工具组。暂缓、调整和只读请求不会由此获得创建许可；问答恢复和重复读取已有确认结果也能保留工具可见性。通用编辑、工具扩展和实现选择仍可使用。
6. 删除两个参考文档中关于 Service 普通文件编辑的矛盾限制，保留 Frontend Tool 向 Agent 暴露操作的应用权限边界。

主系统提示词、主 UI Plugin Skill、压缩提示、上下文预算、执行器和停滞策略保持原样。两个参考文件合计减少 159 字节。没有新增固定开发流程、累计模型调用或图步骤上限；没有修改 vendor、Runtime、维护中的示例 Host 或项目生产依赖。
