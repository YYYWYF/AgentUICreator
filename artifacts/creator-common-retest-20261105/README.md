时间从界面点击发送/确认开始，止于原生 run_receipt；多轮耗时相加，排除等待测试者回答、准备模拟服务、额外截图/行为验证和最终构建的时间。约 11 分 6 秒是模型任务处理时间之和，不是整轮人工操作墙钟时间。

用量只汇总主 Agent 的 model_result；不含未记录的路由/供应商请求。缓存读取是输入的子集，reasoning 是输出的子集，不重复相加。工具使用原生 toolProtocol 计数，包含其记入的参数失败尝试；同一中断/恢复请求只取恢复后的最终累计值，避免重复累加。被拒绝的工具批次与有执行事件的处理器数量可不同，原始协议流一并保留。

## 环境与还原

沿用 deepseek-v4.1-flash、32768 输出、262144 上下文、12000 保留、8192 摘要、温度 0.2、120 秒单次模型超时；原生 Playwright 验证关闭。配置和实际安装包文件哈希见 configuration.json、installed-frontend-snapshot.json。

测试前备份了原临时项目，并恢复首轮问题 1 时的默认模板快照（104 个生成项目文件）。起点是左侧历史栏、reasoning 启用、无 thinking-indicator。之后五题顺序运行于同一 Chrome 会话和同一个项目，不在题目之间悄悄重置，也未手改生成项目来帮模型完成任务。

目标是独立的 creator-connection-host 临时项目。未修改维护示例、Creator 产品代码、主提示词、Skill、文档或 vendor；source-lock 和项目元数据哈希保持原样。沿用已运行的修复版 Creator 和固定的前端安装，不代表验证了其他会话正在进行的仓库改动。记录从 2026-11-05 延续到 Asia/Shanghai 的 2026-11-06，文件夹保留开始日期。

所有提交、选项选择和交互操作均通过原生 CUA 在 Google Chrome 中进行；没有脚本驱动隐藏浏览器替代这次实测。capture.mjs 只读取原生日志、公开协议流和文件快照，不能发送界面请求。

## 行为证据

- **接口**：选择“与现有约定一致、无需鉴权、固定 URL”，再提供 `http://127.0.0.1:47835`。Creator 新增固定地址配置点，沿用已有 HTTP 数据源。关闭临时 Mock 覆盖后，列表出现“自有接口验收会话”，打开后显示“这条历史消息来自本地自有接口。”。
- **布局**：模型实测视口为 992×836，聊天区 `x=0,width=712`，历史与身份条 `x=712,width=280`，相应截图与返回的几何证据一致。
- **思考**：使用已有 thinking-placeholder Mock 场景、2× 播放时长倍率。Chrome 先出现“正在思考...”，没有可展开推理正文，完成后提示与停止按钮消失，显示“思考已完成，开始回答。”。播放控制前后源码哈希一致。此次保留 reasoning 实例并设 enabled:false。
- **头像**：提供 `http://127.0.0.1:47835/avatar.svg`，Creator 在 agent-identity 的项目应用入口通过公开 logo prop 设置默认头像，外部传入 logo 仍可覆盖。浏览器实际请求了图片，截图中清楚显示橙色 QA 图案；未接管 npm 实现或新建插件。
- **共同保留**：最后关闭临时 Mock 连接，重新打开自有接口历史。最终截图同时显示自有历史正文、右侧历史栏和新头像，前面修改没有被后续任务覆盖。
- **最终构建**：目标项目自身 build 脚本成功。该脚本实际执行 Vite/React/Tailwind 的 library build，入口为 Agent.tsx、write:false；这是独立入口的内存构建，不是已落盘的整站部署或干净机器安装证明。脚本、package.json、tsconfig 与日志随记录保存。

## 仍有的问题

1. **接口任务仍查得偏多**：已知配置点后，还反复查传输实现；一次 ls 进入受保护区域被拒绝。最后能完成，但完整三阶段用了 22 次主模型调用。
2. **资料收集有多余轮次**：选择“固定 URL”或“图片地址”后，选择卡本身没有一起收集实际地址，还要再发一次消息。头像选择阶段因尚无 URL 返回 blocked/未完成提示，补齐 URL 后成功；不是这次最终结果失败，但体验不够顺。
3. **思考切换多走了纠正步骤**：尝试读取不存在的 source-registry 路径；把 productized semantic 操作与其他操作混在事务中被准入拒绝，随后拆开提交成功。不存在旧的目标名称门禁导致零写入的问题，但尚不是最短路径。
4. **回复过于冗长**：能力介绍、接口接入和简单头像替换都带了较多内部术语、校验说明和假设性风险提示。

本轮没有继续扩大修改这些工程/交互问题，先保留实际复测结果供评估。真实私有后端、鉴权、历史删除/重命名/归档、消息气泡头像、其他浏览器与真实 Windows 未覆盖，不能据此承诺所有场景都不会出错。

## 测试数据问题与恢复

最初由测试者提供的详情响应遗漏了契约要求的 state.values，并把消息写成了直接 messages。界面显示“历史会话加载失败”和 schema 错误，未崩溃；仅校正 QA 服务数据后，点击重试即成功。错误截图/AX 和成功重试均保留。这不是 Creator 生成代码的错误，也没有通过手改项目源码绕过验证。
