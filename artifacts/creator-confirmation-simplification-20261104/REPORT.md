# Creator 确认流程简化：实现与验证

**机制检查通过；相同模型的原复杂任务仍未通过。**

## 最终行为

- 用户项目 Agent UI 自有代码默认可编辑；现有插件的新交互、辅助模块及配套 Service 不再提交通用新能力审批。
- 新建插件身份前通过原生问答确认一次。工具仅必填 targetPluginId 和 desiredOutcome；不要求先设计完整依赖、文件清单或测试方案。
- 首次接管 npm 插件实现仍通过原有原生问答。模型只需提供 pluginId，实际安装版本、计划哈希、取消信号和应用前复核均由 Host/Operator 处理。
- 保留当前问答结果供恢复执行，不建立逐文件授权台账。已确认插件的后续实现细节不重复询问；接管后的归属和更新 BASE 仍由项目记录维护。
- 验证现有插件可直接指定 pluginId 和 interactions，无需先申请开发批准。交付约定用于验证，不参与已有代码写入权限判断。
- 可选 Service preflight 不弹审批，返回单次 planId；仍检查拓扑、公共声明、文件及引用版本。普通文件工具也可编辑项目 Service。
- 只读请求、项目路径边界、修改前文件版本、生成文件专用修改入口、实际验证、事务恢复和独立更新安装流程保持有效。

## 与重复查询有关的修正

- 自定义插件以 definition.ts 定位时，优先保留同目录真实组件源码，避免最近读取的邻近组件挤掉目标。
- 完整/摘要检查按已读字段识别事实，重复投影视图不再自动等于新证据；加入近期大部分读取重复、但夹杂新文件的恢复提示。没有加入累计模型调用或图步骤上限。
- 原生问答状态同时提供给压缩和主模型；摘要不再设置泛化待审批栏目，也不以文件是否创建推断权限。
- 文档父标题读取返回本节说明与子章节链接，避免从一个父标题连续翻完整本 API。自定义插件没有精确面客文档时，返回公开 API 目录，不按其名称碎片推荐无关内部文档。

## 已完成的验证

- Creator：49 个测试文件、492 项测试通过（最终串行完整运行）。
- 类型检查：Node 和 Browser 均通过；国际化、Operator 契约检查、Creator 构建与离线文档验证通过。
- Operator 源码接管：10 项测试通过。
- 原生 LangGraph：新插件确认后创建配套 Service/插件、实现细节变化不重复询问、普通已有插件/辅助文件直接编辑、交互验证不要求批准、接管同意/拒绝及之后编辑等路径通过。
- 浏览器受控本地模型测试：新插件暂缓、源码接管取消都只出现一次问题，前后源码哈希一致。此测试验证原生问答和 UI，不验证真实模型选择行动的能力。
- 并行运行最终回归时，两项长运行测试触发默认 5 秒超时，继而出现清理目录竞争。保留失败日志 parallel-tests-timeouts.log；同一代码串行复跑 492 项全过，未通过提高超时阈值掩盖失败。
- 实测平台为 macOS；包含中文/空格路径、反斜杠 sourceRoot 与既有 Windows 路径用例，未进行真实 Windows 验收。

## 原任务的真实模型测试

原始输入：给刚才的帮助卡片添加一个“知道了”按钮插件，放进 headerActions。点击后隐藏帮助内容，再次点击卡片标题能重新展开。切换主题后功能仍然正常。

模型 deepseek-v4.1-flash；上下文预算 65536、输出预算 8192、temperature 0.2、单请求 timeout 120 秒。初始源码哈希与此前基线完全一致，生产依赖也复用同一份冻结版本。Agent、Operator 和最终 Host preview 均绑定冻结的 Creator 包。测试未预置模型工具响应或提交方案；只在一次性 QA 项目中通过原生 UI 自动选择“开始开发”。

## 中间试验与边界

保留两个诊断版本：第一次仍要求完整交付约定，第二次已简化问答但发现 API 父章节过度读取。两轮均人工停止后从干净源码重新开始，不把它们当作完整性能对照。最终测试早期存在独立检查的 CPU 负载；单次观察不足以作严格提速结论。

没有在维护中的示例 Host 或真实用户工程做探索性修改。没有修改 vendor、Runtime 或接管真实用户项目源码。工作区原有 install-demo-plugin.ts 修改及其独立反馈测试未改动。
