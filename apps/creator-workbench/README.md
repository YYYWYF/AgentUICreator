# Creator Workbench

`pnpm dev` installs the exact committed dependency graph, rebuilds copied native dependencies for the current platform when necessary, builds the development infrastructure, and starts the Workbench on port 5174 alongside the React platform Host (`examples/creator-host-sandbox`) on port 5180. The left pane previews the real Host URL in an iframe. The Host retains its own independent build and development scripts; Workbench does not import its React application.

Keep `pnpm dev` running while editing. Application files use Vite HMR. Changes under Core, Renderer, Plugins, Runtime or Creator (including Operator, contracts and skills) automatically rebuild the changed package and its downstream packages, then restart both development servers with the previously selected project. Saves are coalesced; build errors remain visible and the next save retries. Active Creator runs and pending confirmations delay the restart until completed or explicitly stopped. Generated outputs are excluded from the watch loop. Existing project application files and source baselines are preserved; template changes apply when initializing a separate test project. This watcher uses the existing command and a TypeScript module, without additional `.mjs` entries.

Creator configuration is read from the workspace root `.agent-ui/creator/.env.local`. `VITE_CREATOR_HOST_PREVIEW_URL` can select another running Host preview. Project inspection, mutation, verification, and mock resource installation use `@za38.03/agent-ui-creator/project/dev`; initialization uses `@za38.03/agent-ui-creator/bootstrap`. Open `http://127.0.0.1:5180/` for the platform template with the Creator Agent dock, or `http://127.0.0.1:5174/` for the full Workbench. The Vue Web Component style-isolation demo is a separate `pnpm dev:vue-host` entry.

The generated Agent exposes generic `observability` callbacks and development observation events. Workbench owns `host-preview.vite.config.ts`, an overlay that reuses the real platform Host Vite configuration and adds the shared `@za38.03/agent-ui-creator/host-preview/vite` and `/dock/vite` plugins only for preview development. The supervisor passes this overlay when starting the Host; ordinary Host commands never load the Creator adapter. It reuses the existing runtime and visual reporters in the Host document, where screenshot capture can see the real Host DOM. Workbench opens a MessageChannel for each iframe load and selected workspace/thread; it uploads reports to its own Creator server with that session's identity. Reload or thread changes close the old channel and reconnect, replaying the latest Host observations. Standalone Host production code has no Creator imports or adapter injection, and production Agent source never imports Creator.

Runtime reporting follows the Workbench's runtime-diagnostics configuration; visual capture requires `VITE_ENABLE_VISUAL_OBSERVATION=true`. Playwright uses the shared supervisor to start Workbench on 5179 and the platform Host on 5180, queries Host UI through `frameLocator`, and retains runtime geometry, screenshot/afterHash, and reload assertions.

Bootstrap accepts an explicit initialization adapter. Workbench composes `initializeAgentUIProject(input, createAgentUIInitializationHost())`; Bootstrap does not import Operator.

Host preparation builds only runtime, Bootstrap, Operator, Source Registry, and Mock infrastructure. `scripts/prepare-workbench.mjs` separately prepares Creator after those prerequisites; both the supervisor and Workbench's package-local `predev` use it. The E2E supervisor also starts its Host on 5180 through the Workbench-owned overlay, retaining the real iframe and observation assertions. Pointing Workbench at an ordinary external Host URL renders that Host but does not inject the adapter; observation reporting requires a preview server started with the overlay.

## Source-only copy on Windows

These are source-checkout development requirements. Install supported Node.js and pnpm 8.12.0, and configure the company npm mirror. From the workspace root run `pnpm dev`. The first launch prepares locked Node dependencies and builds the development tools; subsequent launches reuse current build output. Creator Agent and internal Operator ship in one npm package. See [Creator distribution](../../packages/creator/docs/typescript-distribution.md).

Copy source and lockfiles, excluding `.git`, `node_modules`, `dist`, generated Host `src/agent-ui` / `.agent-ui`, and machine-specific runtime configuration. Keep your model service settings in `.agent-ui/creator/.env.local`; the UI starts without credentials, and actual model requests require a reachable service URL and API key. The Creator configuration remains in the tool host and is not shipped into the generated Agent Frontend.

`pnpm verify:dev-startup` exercises the same supervisor with fresh ports, validates workspace readiness and the authenticated Node Agent proxy, and loads both pages in Chromium. Use `--install-browser` when needed. The `creator-startup.yml` workflow runs this entry on Ubuntu and Windows.

The workspace-root `.agent-ui/creator/.env.local` is read only by the Creator Node tool process for `CREATOR_*` settings. Development preview connections are managed by Creator. Host applications configure their production Agent address through the `endpoint` prop and build independently.

## Maintained Mock Hosts

`pnpm dev:examples` starts the three repository-owned Mock Hosts together without the Creator editing panel. Northstar (`dev:assistant-host`, 5181) and Atlas (`dev:embedded-host`, 5182) retain their original Host designs while Bootstrap initializes current Agent UI templates. See [examples](../../examples/README.md). Stop the existing `pnpm dev` before starting all examples, since both use Platform port 5180.
