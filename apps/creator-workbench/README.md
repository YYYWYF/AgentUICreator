# Creator Workbench

`pnpm dev` installs the exact committed dependency graph, rebuilds copied native dependencies for the current platform when necessary, builds the development infrastructure, and starts the Workbench on port 5174 alongside `web-component-vue3` on port 5180. The left pane previews the real Host URL in an iframe. The Host retains its own independent build and development scripts; Workbench does not import its React application.

Creator configuration is read from the workspace root `.env.agentui.local`. `VITE_CREATOR_HOST_PREVIEW_URL` can select another running Host preview. Project inspection, mutation, verification, and mock resource installation use `@za38.03/agent-ui-creator/operator/dev`; initialization uses `@za38.03/agent-ui-creator/bootstrap`. Assistant and embedded integration remain separate Host examples.

The generated Agent exposes generic `observability` callbacks and development observation events. Workbench owns `host-preview.vite.config.ts`, an overlay that reuses the real platform Host Vite configuration and adds the shared `@za38.03/agent-ui-creator/host-preview/vite` plugin only for preview development. The supervisor passes this overlay when starting the Host; ordinary Host commands never load the Creator adapter. It reuses the existing runtime and visual reporters in the Host document, where screenshot capture can see the real Host DOM. Workbench opens a MessageChannel for each iframe load and selected workspace/thread; it uploads reports to its own Creator server with that session's identity. Reload or thread changes close the old channel and reconnect, replaying the latest Host observations. Standalone Hosts have no Creator package dependency or adapter injection, and production Agent source never imports Creator.

Runtime reporting follows the Workbench's runtime-diagnostics configuration; visual capture requires `VITE_ENABLE_VISUAL_OBSERVATION=true`. Playwright uses the shared supervisor to start Workbench on 5179 and the platform Host on 5180, queries Host UI through `frameLocator`, and retains runtime geometry, screenshot/afterHash, and reload assertions.

Bootstrap accepts an explicit initialization adapter. Workbench composes `initializeAgentUIProject(input, createAgentUIInitializationHost())`; Bootstrap does not import Operator.

Host preparation builds only runtime, Bootstrap, Operator, Source Registry, and Mock infrastructure. `scripts/prepare-workbench.mjs` separately prepares Creator after those prerequisites; both the supervisor and Workbench's package-local `predev` use it. The E2E supervisor also starts its Host on 5180 through the Workbench-owned overlay, retaining the real iframe and observation assertions. Pointing Workbench at an ordinary external Host URL renders that Host but does not inject the adapter; observation reporting requires a preview server started with the overlay.

## Source-only copy on Windows

Install Node.js 20.19.0+ (or 22.12.0+), pnpm 8.12.0 and Python 3.11+ (Python 3.12 recommended), and configure the company's npm/pip mirrors. From the workspace root run `pnpm dev`. No separate `pnpm install`, `pnpm build`, Host initialization or Python environment setup is required. The first launch installs locked dependencies and creates a platform-specific Python cache; subsequent launches verify the lockfile and reuse the cache. Windows supports both `python` on PATH and the `py` launcher, and pnpm may use either its JavaScript entry or standalone `pnpm.exe`.

Copy source and lockfiles, excluding `.git`, `node_modules`, `dist`, `.venv`, generated Host `src/agent-ui` / `.agent-ui`, and machine-specific Python executable paths. Keep your model service settings in `.env.agentui.local`; the UI starts without credentials, and actual model requests require a reachable service URL and API key. The Creator configuration remains in the tool host and is not shipped into the generated Agent Frontend.

`pnpm verify:dev-startup` exercises the same supervisor with fresh ports and a fresh Python cache, validates workspace readiness and the Python proxy, and loads both pages in Chromium. Use `--install-browser` to install Chromium when necessary. The dedicated `creator-startup.yml` workflow runs this entry on Ubuntu and Windows without preparing dependencies, build output, a generated Host, or a Python venv beforehand.

The local file may also contain `VITE_AGENT_ENDPOINT` for development. The Vite adapter explicitly permits public frontend settings only; `CREATOR_*` values remain in the Node/Python tool process. Production builds do not read this file. Host targets read their own project-root `.env.agentui.local`; the workbench reads the workspace-root file. No production `.env.agentui` is required.
