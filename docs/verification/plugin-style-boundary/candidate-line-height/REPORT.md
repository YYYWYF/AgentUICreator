## Blocking failures

1. **A/C official-container typography inheritance.** In the Host, Input is
   16px / normal / 36px high. Inside official DialogContent it becomes
   14px / 20px / 38px high. The narrow Sidebar Sheet has the same difference;
   the desktop Sidebar passes. These containers retain upstream `text-sm`
   utilities. Their children remain unowned and retain their own declared border,
   padding and radius, but ordinary typography inheritance fails the requested
   full computed-style parity. This is recorded as FAIL, not excused as a Reset
   non-match. B's native AntD controls pass these same boundaries.
2. **Restored B Plugin narrow overflow.** The Plugin declares width/height 100%
   plus 12px padding, without declaring its own box sizing. Its 279px container
   contains a 303px content-box Plugin. The old broad Reset had supplied box
   sizing to business content. After browser scroll-into-view, the Plugin starts
   at x=-8px and its left edge is clipped. See
   [B-layout-diagnostic.json](B-layout-diagnostic.json), diagnostic log and four
   failure screenshots. No new box-sizing patch was added to the business
   Plugin or arbitrary business descendants to relabel this as PASS.

No verified minimal repair that preserves official-container typography and
unchanged Host business styles was established for these remaining failures.
They stay blocking. A global descendant Reset, library-specific CSS, or a local
business-control repair would violate this acceptance's constraints.
