# 源码同步与冲突合并 UI 精简

主界面只解释更新内容、已有修改如何保留、用户当前需要确认什么。隐藏源码锁、派生注册表、基线推进等实现用语；路径与代码对比放在可选详情里，以“更新前的原版 / 你的当前代码 / 新版代码”标示。保留独立确认、Creator 合并、自行合并、检查及同步验证操作；尚未合并完成不会显示成功状态。

## 验证

- Creator typecheck、build、check:i18n 通过。
- CreatorPluginUpdates 与 package-update-api 两个测试文件共 12 项通过，新增用例覆盖折叠代码对比、合并尚未确认时不执行同步、冲突校验拒绝与确认后成功状态。
- 真实 Creator + 独立 Host + 实际本地候选 npm 产物。先为临时工程准备 0.0.1 托管源码，安装实际 0.0.2 包，然后在新物理目录打开 Creator，避免旧 Node 解析缓存影响源目录定位。
- 实际 API 分别生成无需合并与需要合并的方案；真实页面展示普通同步确认、冲突合并确认、自行合并后的待确认状态，以及可选代码对比。390px 窄屏无横向溢出，浏览器错误为零。
- 应用层、已有源码修改及托管源码基线保持不变。本轮没有调用模型、没有执行源码同步或采用基线；冲突拒绝/成功采用由交互测试验证，不声称再次完成真实模型合并验收。完整 API 结果见 verification.json。
- 旧 fixture 未修改。本轮生产变更仅涉及 React 展示、CSS 和 locale。截图脚本使用原生路径 API、现有包管理器助手；复制验证工程后关闭原服务，不移动服务仍打开的目录。未进行原生 Windows 验收。
