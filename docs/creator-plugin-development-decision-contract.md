# Creator UI Plugin 复用与开发决策契约

Creator 的普通功能请求先检查当前项目中已安装的 Plugin、已选/启用实例、适用 Slot，以及可安装的正式 Source Item。已有能力足够时，复用并停止开发搜索。正式资源安装是复用，受版本、依赖和定制冲突约束；它不构成新 Plugin 开发。

- **普通定制**：在明确的现有功能上调整文案、样式、配置或既有交互；局部源码变更不自动成为新开发。
- **新 Plugin 开发**：建立新 Plugin 身份，或将已有普通组件薄适配为 Plugin。
- **新能力开发**：增加现有能力无法提供的业务行为；修改旧 Plugin 或共享组件也属于此类。
- **开发方案**：固定业务目标、缺口、目标身份、UI 与数据范围、排除项和检查依据，不预写目标源码。
- **开发授权**：服务端绑定当前真实用户任务或具体方案回答的有界记录。Skill 阅读、普通澄清和模型自报批准均不产生授权。

| 请求语义 | Creator 行为 |
| --- | --- |
| 普通功能需求，现成能力足够 | 恢复、启用、组合或安装正式资源；普通文案、样式、配置和既有交互修改沿用当前目标授权。 |
| 普通功能需求，已确认实质缺口 | 固定业务目标、缺口、证据、UI/数据范围与排除项；在目标工程写入前询问“开始开发 / 调整需求 / 暂不处理”。 |
| 明确委托开发独立 Plugin 或把已有组件封装为 Plugin | 记录当前真实用户请求，准备有界方案；不重复询问是否开发。已有组件优先薄适配。 |
| “现成的先用，没有才开发” | 完整且有效的插件与正式资源检查证明缺口后，激活本任务的条件授权；检查失败或部分结果不是缺口证明。 |
| 分析或明确禁止新开发 | 保持只读或现成能力边界；不从普通澄清、引用文字或历史批准取得开发权限。 |

“新开发”包括新 Plugin 身份、把普通组件适配成 Plugin，以及为需求增加此前没有的业务行为；将新行为塞进旧 Plugin 或应用组件不改变其语义。局部 helper 或 CSS 文件数量不定义开发授权。创建入口只是需要检查的入口之一。

`prepare_ui_plugin_development` 仅在 Creator 服务端建立任务级方案。方案由项目、线程、真实请求、任务、目标身份和范围哈希绑定。直接委托或条件成立生成当前任务 grant；普通缺口生成待决方案，问题沿用 `ask_user_question` 的 checkpoint 和执行权限。开发 Skill 已读取只是知识证据，不是授权。首次创建写入需要当前有效 grant、匹配的 Plugin 身份和当前版本 Skill 阅读证据，并在项目事务锁内校验。

开发授权只覆盖方案内的 Plugin 开发、必要组合、当前 revision 验证和有限因果修复。它不授予 Service Contract、Frontend Tool、Agent 业务操作或任意路径写入。只读 INSPECT 的普通问题回答仍只读；开发需另起明确的顶层可写请求。拒绝和调整是正常的无变更结果，不能回执为功能已交付。新任务、撤销、相关范围变化或失去 checkpoint 绑定使旧授权失效；无关 revision 变化和本任务自己的写入不要求重复批准。

新 Plugin 产出优先采用用户指明的合格自有组件、正式插件或 Source Item、项目认可的公开基础组件与 tokens，再补业务组合。由 AppUIModel 管理布局与实例；UI Plugin 不建立第二 Runtime，不替换上游会话实现。`static_only` 的最终回执只说明当前 revision 静态验证，不声称浏览器或 Runtime 已通过。
