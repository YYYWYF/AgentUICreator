# Creator UI Plugin 编辑与开发确认

用户项目的 Agent UI 源码是默认编辑区域。Creator 按当前需求修改已有插件、增加交互、调整应用层、创建辅助模块或编辑配套 Service，不建立通用新能力审批或逐文件权限台账。

确认后的当前工作上下文按预算保留新插件身份和简短实施合同（能力、位置、生命周期、验证方式），与历史摘要分开。合同说明实现目标，不是逐文件白名单，也不授予额外权限。实际读到的公开 API 签名带模块和安装版本保留；依赖变化后重新检查，不从签名推断运行行为。摘要区分用户需求、系统规则、技能、文档与源码观察的来源，保留冲突而不把技能假设改写成用户要求。

同一修订持续调查时会给出收敛提醒：说明还缺哪项外部事实或哪条指引冲突、下一次读取要解决什么。归档重读不增加新证据；目录尚未创建可以是实施工作。提醒允许继续必要研究或报告冲突，不强制修改代码，不改变只读/取消/审批边界，也不设置累计工具、模型或图步骤上限。

插件编辑/开发流程只在两个操作入口询问：

| 操作 | 行为 |
| --- | --- |
| 修改现有项目插件、已接管实现或其配套代码 | 直接实现并验证。 |
| 新建插件身份，包括把组件封装为新插件 | `prepare_ui_plugin_development` 展示要开发的插件并询问一次；确认后继续实现。 |
| npm 公开 props、children、renderers 等接口无法满足，确需修改其实现 | 通过原有源码接管入口询问该插件的首次接管。包装层漏传公开接口时直接修包装层。 |

原生问答保留当前执行结果供中断恢复使用，避免重复询问。新插件确认覆盖实现所需的新插件源码、辅助文件、父插件修改、组合和验证；文件清单是实现说明，不是写入白名单。实现细节改变不使开发决定失效。取消或调整选择仍按原生问答处理，不写成已交付。

`prepare_ui_plugin_development` 只接受新身份，移除 `extend-capability` 审批分支。相关公开接口/现有源码足以支持判断，不要求全仓搜索或完整 Source Item 目录来证明绝对不存在。

新插件交付约定用于检查创建、注册、组合和交互，不是已有插件编辑或测试的权限前提。`verify_ui_plugin_behavior` 可直接指定现有插件及交互要求，无需先提交开发审批。普通 Service 编辑不弹审批；可选 preflight 工具保留拓扑、公共声明和文件版本检查，返回单次变更 planId。

只读模式、项目路径隔离、修改前文件版本检查、生成文件专用操作、事务恢复、实际验证以及独立的更新安装边界保持由工具执行。接管后的归属、来源和 BASE 仍需记录以支持后续更新与合并。Creator 不创建第二 Runtime，生成前端保持独立部署。

## 宿主 UI 体系选择

Host 通过既有项目摘要的 `uiContext` 提供 package.json 的四类直接依赖声明、包管理器声明和脚本名称，既有组件导航、文件读取与源码检索提供按需证据。`uiStack` 仅为配置的依赖子集；两者均不判定组件库、不证明实际安装或 API 可用。Agent 复用已检查的目标组件、公开接口和当前样式事实，只有存在具体未知项时才补读相关 Provider、封装或主题：优先宿主自研封装，其次实际主流组件库，再组合已有基础组件。不能按库名、版本或 import 数量机械选择。实现记录引用组件和主题路径，不新增决策协议或全仓扫描服务，不读取环境变量/密钥。

仅在没有合适 UI 体系、React 目标兼容且确有必要时建议适配该项目的 UI 依赖，并展示确切新增依赖、实际包管理器和接入修改。依赖安装仍使用已有安装能力和真实安装检查。使用支持这些包的现有 Host 安装能力；当前 Source Item 安装不是通用 npm 安装入口，不支持时明确报告阻塞及用户可执行命令，禁止伪造安装或仅修改声明。确认真实安装与 Provider/样式接入成功后再生成依赖它的插件。拒绝后继续用现有栈。Vue/HTML/Web Components 保持既有桥接，不能把 React Antd 装入消费者作为通用兜底。

自定义插件可复用宿主业务组件；官方插件保持独立 ownership 和升级机制。生成后使用既有 `validate_creator_changes(includeBuild=true)` 执行最终 revision 的静态检查、类型检查及宿主 build；检查 import/Props、授权依赖、样式作用域、主题和国际化。缺少 build 或失败不声称成功。视觉一致性需要独立浏览器证据，未运行时明确未验收。不得修改 vendor、添加 UI Adapter 或改变 Runtime 协议。

新增身份或接管的决定使用原生问答/checkpoint 结果；压缩摘要不重新解释批准、文件白名单或审批范围。源码归属和更新基线仍由项目记录维护。
