## Timeline composition

The Thread extension is message-level, distinct from ToolGroup. Its anchor is the
first ordinary summarizable tool call. Later calls update that same timeline;
text, reasoning, sources, data UI and other parts retain their existing positions.
Every real call in that message projects a step, including the status of dedicated
calls. Tool-name semantics use an exact allowlist; unknown tools retain their name.
Chips contain only short ordinals, never full arguments, commands, paths or results.

Ordinary calls are summarized instead of rendered in a second default ToolGroup.
The timeline starts collapsed. Its expanded composition offers a separate original
details disclosure using upstream PartByIndex and the installed ToolFallback.
Dedicated Tool UIs, MCP apps and nested TaskGroup remain at their original positions
and render once. Waiting approval/input, interrupts and incomplete/error calls stay
outside the collapsed details; action callbacks remain the existing upstream ones.
Failure/cancellation labels do not become success, and the resting summary is neutral
unless every call actually completed.

`stats` is empty: no trusted file-change result contract is currently adopted by
this projection. Arbitrary result JSON is not treated as verified diff statistics.
Removing/disabling Timeline restores the existing ToolGroup path. Slot availability
comes from active contributions in the existing runtime SlotRegistry, not DOM probes.

## Thinking priority and time

ThinkingIndicator and Reasoning remain independent plugins. Creator guidance covers
placeholder-only (Thinking on, Reasoning display off), detailed reasoning (Reasoning
on), and placeholder-to-reasoning handoff (both on). Runtime reasoning is preserved.

Only a running message is eligible. Answer text, waiting actions and approval,
visible detailed reasoning, active Timeline, or an active dedicated Tool UI suppress
the placeholder. Hidden reasoning does **not** suppress it. Without Timeline, a
known running ordinary tool changes the neutral label to Working. Installing the
indicator suppresses the old loading dot; disabling it restores that compatibility
path. There is no reasoning-text analysis or inferred task phase.

The elapsed property uses page-local observation time, clearly labeled as such.
It persists across label changes, resets with active-run/message/thread identity,
and is cleaned up after termination or unmount. Historical/server duration is not
fabricated, and no elapsed value is shown before the local observation reaches 1s.

All product text has en-US/zh-CN parity through the unified locale layer, including
Creator resource/demo names. The official surfaces and current theme tokens are
reused. Focus-visible, wrapping and reduced-motion adjustments are confined to the
product wrappers; no global stylesheet selector or Portal was introduced.

## Templates, demos and compatibility

New Assistant and Platform presets enable Timeline and ThinkingIndicator alongside
Reasoning. Embedded stays opt-in. Existing installed projects were not migrated or
replaced; the existing example Hosts were validated in their current composition.
An existing project must explicitly update its Source Registry/foundation and select
new renderer instances to use these capabilities.

Creator Mock catalog now includes `tool-timeline-thinking` and `thinking-placeholder`.
The latter explains the explicit Reasoning display toggle and does not silently
change existing project settings. Existing error, approval, search and nested-task
demos remain available. The visual test fixture is disposable and may enable all
release plugins without modifying user projects.
