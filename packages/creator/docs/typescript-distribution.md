# Creator TypeScript 发行

Creator Agent 与 Operator 合为一个开发工具 npm 包：`@za38.03/agent-ui-creator`。

- `src/agent`：模型配置、Agent 控制、中断恢复、受控工具、权限、验证、事务和回执。
- `src`：CLI、UI、工程选择、HTTP 宿主、进程生命周期和集成。
- `operator`：内部工程操作、Schema/Registry 校验、安装、源码接管和更新。
- `contracts/creator`：canonical JSON Schema、工具合同和 fixtures；构建后复制至 `dist/contracts`。
- `skills`：随 npm 包交付的只读领域知识。

构建和运行 Creator 使用 Node.js 22（最低 `22.0.0`）或 Node.js 24（最低 `24.22.1`），声明范围为 `^22.0.0 || ^24.22.1`。仓库通过 `.nvmrc` 固定最低验证版本 `22.0.0`，使用 pnpm 8.12.0；CI 在 Windows/Linux 上覆盖 `22.0.0` 与 `24.22.1`。用户安装后由当前 Node 可执行文件启动 Agent 子进程，切换 Node 后需要重启已有 Creator 进程。API 使用 `CreatorProcessManager`、`CreatorClient`、`createCreatorClient` 和 `CREATOR_AGENT_MODE`。

```text
pnpm install --frozen-lockfile
pnpm --filter @za38.03/agent-ui-creator build
pnpm --filter @za38.03/agent-ui-creator typecheck
```

浏览器请求继续使用既有 AG-UI 路径。用户问答继续通过 Creator 自己的 `on_interrupt` / `on_interrupt_resumed` 投影，使用当前线程和检查点恢复，保留权限；进程重启不会恢复内存检查点。事务仍位于 `.agent-ui/creator/transactions`，撤销必须检查所有文件的当前 hash，保留后续用户编辑。

任务由选中工程的 Creator 子进程持有，HTTP 连接只是事件订阅。Host 热更新、整页刷新或面板重载不会取消任务；面板在同一标签页中恢复原线程和任务 ID，从本轮执行前的会话重放事件，避免重复提交修改。短暂断线按已收到的字节位置重连。事件暂存在工程本地 `.agent-ui/creator/run-streams`，此记录用于当前进程中的订阅重放，不是跨进程恢复检查点。停止按钮仍显式取消任务；切换或关闭工程会停止旧工程的子进程。Creator 服务重启后，面板会提示检查已保存修改，再开始新请求。

仅交付源码时，Plugin 必须在 Host 的源码目录中可发现且通过当前修订的静态验证；不为满足 Runtime 目录检查而新增 AppUIModel 实例。Runtime 目录仍只包括已经选中的 Plugin，完整应用交付仍要求真实组合与相应运行验证。失败或停止后，已保存的修改通过回执保留撤销入口。

生成的 Agent 前端继续独立构建和部署。Creator 不进入其生产依赖或浏览器模块图。Core、Renderer、Runtime、Plugins 与 Web Component 继续独立版本；公开 API 包总数为六个，Operator 不再单独发布。

常见组件修改可使用只读 `inspect_ui_edit_context` 聚合 owner 定位、应用源码与样式读取、安装版本 API 和使用指导。普通插件检查与文件工具仍然可用。源码采用同一套读取范围和 hash 证据，不能凭缓存摘要编辑，也不提供新的开发或源码接管授权。

首轮执行模型默认收到当前工程的精简 Plugin 目录：名称、功能、启用状态、实例位置、应用入口与既有配置 owner。Host 在每轮权限判定后从权威 Composition 检查生成这些事实；不增加模型路由，不预读实现或完整 API，不把目录当作源码读取、授权或验证证据。插件增删和状态变化会在后续轮次重新获取；读取失败明确标记未知，通用文件检查和恢复仍可继续。

权限分类使用结构化 JSON 输出，将当前请求与最近两轮历史数据分开；只有端点明确不支持 JSON Schema 时才尝试 JSON object，所有结果仍严格校验，失败不授予写权限。

按行编辑工具保留相邻行边界与原文件 LF/CRLF 风格；文件 hash 与已读范围检查保持不变。

首轮插件目录、单插件与编辑上下文检查同时返回目标安装包声明的公开组件展示说明（若存在），区分组件部件、props 和样式作用对象。说明由 Plugins catalog 持有，Operator 按真实模块/组件读取并限制字段和长度；缺失时不借用其他模块或版本的说明，不提供源码接管授权或运行效果证明。

源码快照忽略 `.vite` 等生成缓存，普通工程内容仍受原有容量保护。快照、事务或文件清单超过 Host 硬容量时，返回具体阻塞错误，不让模型反复重试同一容量失败。

连续微调使用按工程真实路径和会话隔离的进程内编辑工作集（最多 64 个，闲置 20 分钟失效）。下一轮重新判断权限并校验工程、安装目录、owner 和文件内容，再预读最近编辑区域；不复用授权、图 checkpoint、类型或验证结果。进程重启、源码/依赖变化、冲突或放弃中断会使相关工作集失效。此机制不改变累计调用无限制、取消、事务、验证或通用工具能力。

工作集也从普通项目检查和实际文件修改自动建立，不要求模型调用专用定位工具。已知 catalog owner 优先；直接修改的单一工程文件可作为文件导航记录。切换修改文件时更新工作集，跨 owner 或过大修改保守退出，下一轮预读实际改动附近的源码，不重放旧工具结果。

同轮重复 composition 检查在工程文件内容、元数据和安装 catalog 身份一致时复用；失败不缓存。项目检查默认省略重复的 Plugin 描述、意图和实例位置文案，保留身份、绑定、实例、AppUIModel 和操作字段；`detail: "full"` 返回完整检查，单插件检查继续提供完整 API。静态验证仅在同轮、同 mode/修订/工程内容且先前成功时复用，`force: true` 可重新执行；build、权限、运行证据和修改操作始终不复用。检查还依赖工程之外的可变输入时，应使用 `force: true` 重新执行，不能把项目内容指纹视为那些外部输入的证明。

工具批次允许不含 build 的静态验证与独立只读检查一起执行。提供方一次返回多项普通文件编辑时，Host 按原顺序逐步执行，每步保留权限、当前 hash 和已读范围检查；前项失败后，后项明确返回未执行。此队列只接受 `edit_file` / `edit_file_from_read`，不增加授权，不承诺跨文件原子性；部分成功仍由实际事务回执记录。Operator 修改、build、问答、授权和工具组展开仍须单独调用。

缓存指纹有文件数和字节预算。工程过大或指纹无法完整读取时，关闭本次复用并执行原 Operator/验证流程，不能让缓存优化新增工程准入限制；文件 no-op 继续使用该工具已读取的文件 hash 和工程元数据验证。取消信号始终传播。

写入请求没有实际修改时，模型文字不能单独证明完成；需要经过验证的目标条件、受控 no-op、用户拒绝、开发决策或事务恢复记录。只读工具 `verify_creator_outcome` 可核对插件有效启用状态或工程文件的精确文本；未知插件和不可用证据不算满足，收尾时重新检查条件。此证据不代表 Runtime 验证，也不授予源码读取或修改权限。无执行证据便结束的响应会收到仅针对本轮实际回执的完成检查反馈，同一未变更修订最多重试两次无证据停止，中间插入只读工具不会重置；仍无证据时返回 `blocked` / `CREATOR_NO_COMPLETION_EVIDENCE`，保留原有回执与重试路径。这不限制持续有进展任务的累计调用，不增加常驻系统提示词，也不替代任务效果和真实界面的验收。

开发验证包括 TS 类型检查、生产边界检查与 i18n 检查；产品功能以真实浏览器中的检查、修改、确认、停止、恢复与撤销场景验收。macOS 浏览器结果不代表真实 Windows 验收。

公开类型查询只向模型投影所查询的安装 API，保留完整查询结果中的签名和缺失标记，不重复无关插件清单；普通插件检查继续返回完整所有权与编辑导航。工作上下文按预算保留已批准的实施目标和带版本的实际 API 观察，不把它们视为权限、新鲜源码或运行验收。依赖变化后重新检查 API。

摘要输出预算独立于 Agent 输出预算：`CREATOR_CONTEXT_SUMMARY_MAX_TOKENS` 默认 8192，且不超过 `CREATOR_MODEL_MAX_TOKENS`。摘要目标为简短的有来源事实、已选实现和真正未决问题；首次触发压缩后为后续工具往返保留余量，避免摘要越积越大。两种预算都保留单次请求超时和用户取消，不设置累计执行上限。

长任务默认先归档超预算的大型成功只读工具结果，通过 `read_creator_context` 按 JSON 路径及有界字符页取回，再对剩余超预算历史启用摘要。归档仅作用于模型输入；原结果保留在 checkpoint。运行内快照不访问任意路径、不跨运行授权、不刷新文件观察；错误、事务、交付和修改证据不归档。复用当前 LangChain 的摘要中间件，对消息副本安全分段并缓存递进摘要，原始 checkpoint、工具日志和事务保持完整。摘要不会代替权限、文件读取/hash 或行为验证证据；最新用户请求保留原文。`CREATOR_CONTEXT_MAX_TOKENS=65536` 配置包含系统提示、工具 Schema、消息和输出预留的估算预算，`CREATOR_CONTEXT_KEEP_TOKENS=12000` 配置近期消息保留目标。单个工具批次过大时，用只读文本片段连续摘要，全部片段成功后才采用结果；每次压缩都必须吸收新历史，不能只重复摘要缓存。原始工具配对和完整内容保持不变。未知模型没有可依赖的窗口信息时使用这些明确预算，部署方可调整，不能把字节启发式估算当作提供方 tokenizer、精确用量或严格上界。`CREATOR_CONTEXT_COMPRESSION=0` 可用于关闭归档和摘要的对照测试。摘要使用当前模型与独立提供方会话，支持取消和既有单次请求超时；失败不丢弃原消息，日志与回执分别报告摘要调用次数/耗时及执行调用，服务端实际 token 另记。此配置属于工具 Host，不进入生成前端的生产配置或依赖。

摘要模型的超时和临时网络故障沿用 `CREATOR_MODEL_MAX_RETRIES` 的重试配置；每次尝试使用独立提供方会话并计入摘要调用次数和耗时。取消会立即结束等待，重试耗尽保留原始错误及消息，不采用中间件的错误文本作为摘要。

原始 checkpoint 的生命周期仍由 Runner 管理：中断等待答案时保留，正常结束或异常退出后按现有策略清理。运行日志及工具流继续保留。快照句柄只在当前运行及其进程内中断恢复期间有效。

摘要可能缩写历史快照 ID；使用 `read_creator_context({ artifactId: "list" })` 可按同一字符分页规则重新发现本次运行的完整 ID，再按 JSON 路径读取。目录同样是历史数据，不授予新文件读取或修改权限。
