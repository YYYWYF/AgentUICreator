# 验证定制与自定义 Plugin

验证围绕用户目标和受影响合同，不用测试去复述每一行实现。先运行工程已有的 `test`、`typecheck` 和 `build`，再检查实际页面。

## 测试连接与数据

需要隔离真实后端时，可使用 Core 的 `/testing` 入口构造测试连接，或使用[模拟联调](../guide/mock/)验证事件展示。测试连接仅用于测试；构建通过后仍需在实际页面和业务服务中验收。

## 选择状态

组件至少检查空态、加载、运行、完成、错误、取消和不可用中与它相关的状态。服务 Plugin 通过消费者验证，不要求给没有 DOM 的 provider 制作空截图。

renderer 使用合法与无效 payload；审批覆盖允许、拒绝、取消和过期；附件/语音覆盖权限和适配器失败；历史覆盖只读和恢复条件。

## 生命周期与样式

验证启用、停用、重新激活、连接切换和卸载清理。历史加载、重挂载及 StrictMode 不重复副作用。检查 Host 全局样式、弹层容器、滚动、窄屏、焦点与 screen reader 标签。

两种语言核对 key、占位符和实际显示，主题切换不丢草稿。路径相关改动要覆盖 Windows 盘符、空格、中文和逻辑路径规范，不以 Linux 通过宣称 Windows 验收。

## 记录结果

```text
目标：窄屏保留发送入口且无横向溢出
环境：工程、依赖身份、视口、语言、主题、Agent 来源
静态：实际命令与结果
交互：发送、停止、错误与键盘
未验证：真实后端权限、恢复或平台缺口
```

独立生产构建检查 Creator 和开发 Mock 不进入依赖图。源码同步要在当前文件和实际升级后的依赖上验证，旧回执不能代替新检查。

> 截图待补：按上述目标拍正常、窄屏、失败与焦点状态；静态回执单独保存，不用其替代视觉结果。
