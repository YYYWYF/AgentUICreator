# 把某个 Plugin 实现交给项目维护

普通颜色、文案、组合和展示调整，先改项目已有组件参数。只有公开参数无法满足时，才考虑把某个官方 Plugin 的实现源码放入项目维护。

## 接管前确认

让 Creator 先说明具体 Plugin、当前安装版本、将增加或切换的文件、保留的定制与检查方法。阅读后明确同意。一般的「调整界面」请求不包含接管其他组件的授权。

## 接管后的维护范围

项目会拥有该 Plugin 的实现文件，并继续使用现有应用层参数、页面布局和实例身份。查看预览确认效果，再运行自己的检查。之后可以继续修改这个已接管组件，但不会自动接管其他 Plugin。

保持官方上游文件原样，优先在产品适配文件中实现定制；不要为一个组件调整复制或改写共享运行层。

## 后续更新

升级 npm 不覆盖你的组件文件和布局。需要采用新版实现时，从[源码更新](../updates/source-sync)阅读差异、合并并验证，再明确确认采用。只移植一个修复不表示完整升级。

旧工程已有定制先保留，迁移另行说明影响，不自动改成新的包引用。出现参数不兼容时先规划适配，不覆盖业务代码。

> 截图待补：接管前的具体文件计划、接管后的项目文件与预览，以及已有布局和定制保持不变的对照。
