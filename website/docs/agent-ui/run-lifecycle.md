# 运行状态、排队与恢复

一次运行从发送请求开始，可能以完成、错误、取消或等待用户输入结束。看到传输结束不等于业务任务成功，界面应同时保留实际运行状态。

| 状态 | 用户可以做什么 |
| --- | --- |
| 运行中 | 阅读增量输出，必要时停止；队列可用时添加后续消息。 |
| 等待输入 | 回答问题、审批或表单，随后等待继续。 |
| 完成 | 查看最终回复和输出结果。 |
| 失败 | 阅读错误，确认服务状态后选择重试。 |
| 已取消 | 查看保留内容，决定重新发送或继续处理。 |

## 排队消息

消息队列是可选能力。它保存尚未发送的后续输入，不能当作已经收到回复的聊天记录。关闭页面或切换上下文后是否保留队列，以项目当前实现为准，不承诺持久化。

## 刷新后恢复

恢复要求后端保留运行身份和事件流，并由加载会话返回可恢复信息。浏览器本地看到旧文字、线程 ID 一致或 Mock 能演示恢复，都不足以证明业务服务支持恢复。

重新打开会话后先查看加载与运行状态。恢复失败时记录线程和运行标识、请求错误及最后收到的事件，不要反复发送相同业务指令冒充恢复。

SubAgent 任务卡片仅展示主 Agent 返回的数据，不代表浏览器分别连接了多个 Agent Runtime，也不意味着SubAgent前端工具执行已经支持。
