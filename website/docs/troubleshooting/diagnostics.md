# 收集诊断信息

遇到问题时，先按[故障排查入口](./)确定它发生在 Creator、生成应用、业务 Agent 还是发布过程。本页说明各类问题应从哪里取证，以及怎样提供可复现的信息；使用 Mock 和真实服务时都适用。

## 选择对应证据

| 问题发生在哪里 | 优先查看 |
| --- | --- |
| Creator 安装或启动 | 启动终端中的原始错误、工具安装目录和实际版本。 |
| Creator 修改任务 | 对应运行的文件差异、验证命令、退出结果和最后一条执行活动。 |
| 页面没有更新 | 当前工程与页面地址、开发服务器输出、浏览器控制台和实际加载资源。 |
| Agent 不回复或状态异常 | 请求 endpoint、HTTP 状态、响应事件，以及 thread/run/toolCall 标识。 |
| Plugin 或业务适配器 | 已启用的插件、服务是否可用、输入数据及错误提示。 |
| 升级或构建失败 | 升级阶段、计划与执行回执，或第一条相关构建错误。 |

Creator 的文件与验证项可以在[回执](../guide/receipts-and-validation)中展开。若开启额外调试记录，先按[工具配置](../guide/configuration)核对用途；缺少预览证据时保留未观测状态。

## 写出最小复现

记录操作目标、执行步骤、实际结果、预期结果和发生时间。同时提供工程及依赖版本、操作系统、语言、主题和 Agent 来源。

使用 Mock 时记录场景 ID、播放倍率和所需资源；使用真实服务时记录请求标识与最后收到的事件。更换来源后现象不同，是定位线索，仍需检查实际服务。

## 提交前处理敏感内容

移除模型密钥、Cookie、Authorization、个人信息、业务内容和私有文件链接。保留错误码、字段结构及必要的调用身份，无需提供完整模型回复或整个项目。

停止操作、请求结束或静态检查通过都不能单独证明问题已经解决。修复后，重新执行同一组最小步骤，并说明实际通过与尚未验证的部分。

> 截图待补：展开的验证回执、脱敏网络错误与最小复现材料，分别标注证据来源。
