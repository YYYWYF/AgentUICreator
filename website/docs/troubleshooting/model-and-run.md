# 模型请求失败、任务停滞和取消

## 请求失败

核对 `--config-root`、环境变量优先级、服务地址、准确模型名和凭据。401/403 查模型服务授权，404 查路径/模型，超时查网络和服务时延。改配置后重启 Creator。

服务返回缺 `x-opencode-session` 时才启用对应专用配置。不要为所有提供商增加无关头，也不要通过扩大文件权限修复网络问题。

## 看起来停住

先看是否等待问题卡片、构建命令、安装或工具错误。记录最后完成步骤和新日志。Creator 没有固定累计调用上限，但单请求超时、无进展检测与取消仍生效。

构建无进展时检查原进程和输出；不要反复提交相同请求。需要停止时点击停止，等待结果后读取差异与回执。

## 取消后的文件

结果可能是未改动、已保留修改或状态不明。停止不等于撤销，先检查当前文件，再选择继续或受控撤销。未知安装进程按[恢复](../updates/recovery)处理。

## 恢复验证

先用只读问题验证模型，再在当前差异上继续原任务。旧确认过期时重新规划，不直接复用。支持材料包括脱敏状态码、模型标识、最后活动和回执，不包含 key 或完整 raw trace。
