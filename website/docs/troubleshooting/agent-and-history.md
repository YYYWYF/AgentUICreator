# Agent 不回复、历史或恢复失败

## 没有回复

先区分消息没发出、HTTP 失败、流无事件和 renderer 未展示。查看浏览器请求 endpoint、状态码、响应流，核对直连/开发转发及当前 Agent 来源。

检查 CORS、登录会话、代理缓冲和 HTTPS。模型 JSON 不是 AG-UI 流，ready 也不证明接口健康。用 simple-chat Mock 成功可帮助定位后端链路，但不能证明真实 Agent 合同正确。

## 历史加载

核对 conversationDataEndpoint、会话 ID、列表与详情返回结构。列表失败不能按空数据处理；旧记录可能只读，不能强行启用发送。认证和数据权限需在历史 API 同样生效。

## 运行恢复

后端需要保留运行并提供对应线程的 resume stream。只有保存 threadId 或浏览器旧消息不够。核对加载数据中的恢复能力、runId、最后事件和取消信号。

不通过重新发送有副作用的用户请求冒充恢复。切换线程后旧事件应留在原线程，若串到新会话先检查绑定归属。

## 材料与验证

提供脱敏 thread/run/toolCall 标识、事件顺序、状态码和复现步骤。修复后验证正常、错误、取消、重载和切换，分别记录 Mock 与真实服务结果。

> 截图待补：请求失败、事件到达但无 UI、只读历史和恢复失败的不同证据。
