# 撤销与重新应用修改

Creator 的文件事务可以在条件允许时撤销，并在撤销后重新应用。入口位于对应运行的变更回执中，只在当前事务可操作时显示。

## 撤销本轮

1. 等待运行和问题卡片结束。
2. 找到要撤销的回执，核对文件范围。
3. 点击该回执的撤销操作，等待结果。
4. 检查差异及页面，再运行受到影响的工程检查。

文件在事务完成后被手动改动、被其他任务修改或出现状态冲突时，撤销可能被拒绝。先读取当前差异，保护后续改动，不要强制覆盖来让按钮成功。

## 重新应用

撤销成功且仍可重新应用时，回执提供对应入口。操作恢复的是该事务的文件修改，不是重新运行原任务；原回执的验证结果不代表重新应用后的当前工程仍通过。

## 适用范围

这套机制不是 Git 历史管理，也不是所有外部效果的回滚。依赖安装、缓存、生命周期脚本、已发送网络请求等可能有独立恢复流程。涉及 npm/pnpm 更新时，按[升级失败恢复](../updates/recovery)检查声明、锁文件和实际安装是否均恢复。

如果没有可撤销按钮，读取回执说明。可以在版本控制中审查本次差异并有选择地恢复，但要保留本轮之前和之后的其他编辑；不要对整个工程做无范围的重置。

> 截图待补：可撤销、已撤销可重新应用、冲突不可撤销三个状态；展示范围和原因，避免把原运行验证展示为重新验证。
