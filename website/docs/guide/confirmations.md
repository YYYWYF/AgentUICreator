# 回答澄清与确认变更

Creator 在缺少信息或需要确认具体变更时，会把问题显示为卡片。等待回答期间，普通输入、切换工程和部分命令会暂时不可用；先处理当前问题。

## 回答卡片

阅读问题和选项，根据卡片支持的方式选择选项或填写文字，再提交。可以补充路径、范围和验收条件；路径应指向当前工程，敏感凭据放在服务端配置文件中。

不希望继续时，使用卡片提供的取消操作。取消当前决定和停止运行的结果应以随后状态为准，不代表已经写入的所有文件自动恢复。

## 分清确认范围

| 确认对象 | 需要核对 |
| --- | --- |
| 普通代码修改 | 目标区域、涉及文件、保留项及验证方式。 |
| 首次源码接管 | 准确 Plugin ID、实际安装版本、提取目录、将切换的实现 import。 |
| npm 依赖升级 | 当前与目标精确版本、兼容清单、锁文件、安装及恢复范围。 |
| 已接管实现同步 | 原始版本、本地修改与目标版本、冲突、受保护应用层及验证要求。 |
| 采用新基线 | 完整合并已经验证，准备记录这次采用的新版本。 |

普通应用层定制不需要接管实现；已同意接管某个 Plugin 也不覆盖其他 Plugin。依赖升级和源码同步是不同阶段。

## 问题过期或提交失败

如果工程、版本或原问题上下文发生变化，旧卡片可能无法继续。不要复制旧确认并声称仍有效；刷新状态，让 Creator 重新生成基于当前工程的方案。提交失败时，先看卡片是否仍待回答，避免重复触发相同变更。

> 截图待补：普通澄清、逐 Plugin 接管计划、过期问题各一张；展示可审查的对象和范围，隐藏真实目录或业务数据。

运行行为见[进度与取消](./progress-and-cancel)，更新操作见[项目依赖升级](../updates/package-upgrade)。
