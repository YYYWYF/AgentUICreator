# 增加新的界面功能

本页于 2026 年 11 月 6 日使用当前 Creator 和 `deepseek-v4.1-flash`，在准备好的招行 AI 工作台中重新执行。本轮已实际新增“当前工单”卡片。

## 本次怎么说

> 请在当前 AI 工作台的对话区上方新增“当前工单”卡片。卡片显示工单号、标题和状态；没有选中工单时隐藏，Host 切换选中工单时更新。点“查看详情”打开现有详情抽屉。提供“隐藏当前工单”和“显示当前工单”操作，隐藏保留数据和配置，恢复后仍显示当前 Host 选择。读取失败时用简洁业务提示和“重试”重新读取。中英文都要有，保留现有布局、会话、输入和回复操作。

本轮另外提供了已有演示服务的文件与接口说明：同步读取当前选中工单、订阅选择变化、打开详情，不在挂载或切换会话时发起查询。工单状态使用 `pending`、`processing`、`resolved`，只翻译界面显示文字。

这组接口来自本地演示工程，不是所有项目默认具备的服务；接入自己的页面时，需要提供对应说明。

## Creator 实际怎样处理

Creator 检查工程后，提出新增项目自有卡片插件及其放置位置。确认该具体方案后，它创建了卡片、共享双语文案和局部样式，再通过受控工具将卡片放在左侧对话区上方。没有接管官方插件源码，右侧会话列表仍为 240px。

![新增当前工单卡片后的实际修改回执。](/images/guide/examples/20261106/current-ticket-reply.jpg)

本轮经过了较多工程检查和多次装配调整，最终类型检查及修改校验通过。下面的交互由浏览器另外检查。

## 页面检查结果

没有选中工单时，卡片不显示。在服务工单页面选择 `FW-20261022-001` 后，AI 工作台显示对应标题和“待受理”：

![实际新增的当前工单卡片，左侧聊天、右侧会话列表保持原样。](/images/guide/examples/20261106/current-ticket.jpg)

点击“隐藏当前工单”后只保留恢复按钮；在此状态下新建会话，再点击“显示当前工单”，仍恢复同一张 Host 选中的工单：

![隐藏后保留恢复入口，新建会话没有丢失恢复能力。](/images/guide/examples/20261106/current-ticket-hidden.jpg)

点击卡片的“查看详情”，实际打开工作台已有抽屉，工单号与标题一致：

![卡片打开已有工单详情。](/images/guide/examples/20261106/current-ticket-details.jpg)

切换英文后，标题、状态与操作按钮使用英文；工单标题是业务数据，继续保留其原始内容：

![当前工单卡片的实际英文界面。](/images/guide/examples/20261106/current-ticket-english.jpg)

随后在业务页面改选 `FW-20261022-002`，返回平台助理后，卡片更新为“手机银行登录设备变更 / 处理中”。检查期间没有记录到卡片发起查询的请求。

![Host 改选工单后，卡片显示新工单及对应状态。](/images/guide/examples/20261106/current-ticket-changed.jpg)

本轮没有注入同步读取异常，因此不把“读取失败后重试”列为已完成的浏览器验收；该分支已实现并经过类型检查。

希望自己实现时，见[创建自定义插件](/development/create-plugin)；检查方法见[检查修改结果](/guide/examples/verify-results#检查清单)。
