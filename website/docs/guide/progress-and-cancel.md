# 查看执行进度与停止任务

发送需求后，对话区会显示实际发生的分析、工具活动和回复。任务耗时取决于模型服务、工程规模和检查命令，活动数量不是完成质量的指标。

## 阅读进度

区分正在读取、正在编辑、正在验证、等待回答和执行失败。等待问题时必须回复卡片；安装或构建期间应根据日志判断是否仍有进展，不要只看最后一条自然语言回复。

复杂任务可能持续较久。有新活动或检查输出时可以继续等待；长时间没有进展时记录最后完成的操作和错误提示，再决定停止或排查。请求超时不表示之前的文件修改已撤销。

## 停止任务

点击底部「停止执行」，等待停止结果。按钮显示停止中时不要重复提交。随后阅读本轮结果：未改文件、已有修改被保留、或修改状态暂不能确认，这三者需要不同处理。

停止不是撤销。若已经产生修改，先查看文件差异和事务回执，再决定是否继续、手动调整或[撤销本次修改](./undo-redo)。依赖安装的恢复范围另见[升级恢复](../updates/recovery)。

## 中断后继续

保留原任务上下文，说明要接着处理的剩余目标。例如：「基于已保留的改动，先检查当前差异和检查结果，再修复尚未通过的类型错误。」不要直接重做初始化或删除已有目录。

重启工具或刷新浏览器后，先核对工程及当前文件状态。浏览器保存了对话不等于外部子进程、安装操作或业务 Agent 运行已经恢复。
