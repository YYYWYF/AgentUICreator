# 检查结果与错误状态

本页集中解释 Creator 回执中的状态。需要了解在哪里展开文件差异、检查命令和页面验收时，先看[阅读回执](./receipts-and-validation)。

## 常见结果

| 你看到的结果 | 如何理解 | 下一步 |
| --- | --- | --- |
| 没有项目修改 | 本轮只回答、检查或按你的决定结束。 | 需要实施时再明确提出修改。 |
| 已保留修改，结果尚未确认 | 文件可能已经改变，但任务没有得到充分验证。 | 查看差异与失败原因。 |
| 静态验证通过 | 已执行的类型/构建等检查通过。 | 到实际页面确认效果。 |
| 静态验证未完成或失败 | 缺检查或某项检查报错。 | 展开命令输出，修复后重查。 |
| 页面更新未观测到 | 没有证据证明当前预览使用新代码。 | 核对工程地址、热更新或旧产物。 |
| 请求目标未满足 | 结果未达到本次约定。 | 描述仍不符合的现象并继续调整。 |

## 失败信息

优先保留具体错误码、检查命令、第一条相关错误和复现步骤。界面无法打开、模型调用失败、业务 Agent 不回复及 Plugin 无数据分别走[故障排查](../troubleshooting/)。

不要把停止、请求结束、复制成功或局部构建通过理解为整个业务任务完成。重新应用已撤销的改动后，需要再次验证当前页面。

## 提交支持材料

按[收集诊断信息](../troubleshooting/diagnostics)整理复现步骤、版本和脱敏回执；该页统一说明各类日志的来源与提交范围。

> 截图待补：正常通过、静态未完成、页面未观测和停止后保留修改四种实际回执。
