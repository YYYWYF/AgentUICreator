# 理解修改结果与验证回执

回执描述本轮实际改变了什么、运行了什么检查，以及哪些结论还有证据缺口。普通咨询可能没有修改回执，不应为了展示完成状态制造文件变更。

## 先看文件，再看结论

展开文件项，检查新增、修改、删除及差异。差异可能截断，需要时直接查看工程文件。确认改动属于本次请求，没有覆盖其他 Plugin 或应用层已有定制。

再展开验证项，查看命令、退出结果和输出。区分本轮检查与原先运行的检查；工程文件在检查后又改变时，旧通过结果不能代表当前版本。

逐项状态含义和下一步见[结果状态对照](./validation-results)。本页侧重在哪里查看差异、怎样核对检查，以及如何进行页面验收。

## 处理失败和未验证

记录失败命令及第一条有意义的错误。如果是已有工程问题，说明它与本次变更的关系，不要把所有失败都归因于模型。需要继续修复时，将回执中的准确失败信息交给 Creator。

源码同步后，还要确认应用层共享 API 兼容，不能只看合并无冲突。重新应用已撤销的事务后，原运行验证只是历史记录，必须重新检查。

## 做页面验收

在当前工程预览中验证目标区域、空态、运行、失败和窄屏。审批、附件、认证与恢复必须使用对应服务或明确标记的 Mock；截图无法证明真实后端功能已经可用。
