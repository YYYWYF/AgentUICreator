# 检查修改结果

Creator 的修改回执用于查看改了什么、哪些代码检查通过。页面显示和点击行为还要在助理中实际操作。本页截图来自 2026 年 11 月 6 日的招行 AI 工作台，保持左侧聊天、右侧会话列表。

## 让 Creator 说明检查范围

可以继续发送：

> 帮我检查刚才改的地方。工具成功、失败和需要我确认时，都能正常显示吗？哪些已经检查过，哪些还需要我在页面上试？

把它已经执行的代码检查与仍需手动检查的页面状态分开核对。没有运行浏览器的回执，不代表已经检查过实际交互。

## 正常回复与工具失败

本轮在浏览器中发送消息，分别运行「思考、调用工具并回答」和「工具调用期间发生错误」两个 Mock 场景。

| 检查 | 实际结果 |
| --- | --- |
| 正常回复 | 思考、工具记录和最终回答正常显示；工具组可以展开 |
| 工具失败 | 工具组标记调用失败，页面显示服务不可用的说明 |
| 重新生成 | 点击「重试」后重新生成，回复区出现新的分支记录 |

## 审批与继续回复

分别运行「工具审批 · 旧版 CUSTOM 格式」（`approval-legacy`）和「工具审批 · 新版 interrupt 格式」（`approval-resume`）。新建项目默认启用的 `tool-result` 已包含审批区。展开工具组，检查请假方案的说明、参数和「允许」「拒绝」按钮。

每个场景分别新建会话检查两种选择：允许后返回方案已确认的结果并继续回复；拒绝后返回取消结果并继续回复。旧版请求使用 `forwardedProps.command.decisions`，新版请求使用带原中断 ID 的 `resume[].payload.decisions`。若服务同时返回两种格式，审批按钮应只出现一组。

这些是当前两种格式的检查步骤。上方正常回复与工具失败的截图不作为这两个审批场景的浏览器验收。Mock 仅返回演示结果，不办理真实请假；启动与连接方式见[检查页面交互](/mock/getting-started)，完整协议见[审批数据接入](/plugins/tool-fallback#显示条件与数据来源)。

## 复制、导出与重新生成

回复底部提供「复制」「重试」和「更多操作」。本轮点击复制后核对了剪贴板内容；从更多菜单下载 Markdown 后，也读取了实际下载文件，确认包含页面回答。

![在回复底部的更多操作菜单中导出 Markdown。](/images/guide/examples/20261106/actions-export-menu.jpg)

点击「重试」后，助理再次完成回复，页面显示第二个回复分支：

![重新生成完成，回复区显示第二个分支。](/images/guide/examples/20261106/verify-regenerate.jpg)

## 检查清单

对照原始需求检查修改区域和要保留的功能。涉及文案时，检查页面文字与点击后实际发送的内容；涉及语言时，检查切换前后的草稿和当前会话；涉及业务服务时，检查实际接口、空结果和失败重试。

把页面上看到的具体偏差继续告诉 Creator，再查看新回执和页面。代码检查、Mock 回放和真实业务接口各自检查对应范围。
