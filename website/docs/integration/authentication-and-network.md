# 请求认证与网络部署

认证由业务 Host 与 Agent 服务负责。用户头像、`userId` 展示字段、登录按钮和客户端门禁都不能替代服务端会话与权限校验。

## 选择网络路径

沿用业务同源 API 或网关，例如浏览器请求 `/api/agent`，业务网关转发。跨域时配置允许来源、方法、请求头及凭据策略。HTTPS 页面避免混合内容请求。

生产不依赖 Creator 开发转发，也不把模型 key、服务令牌或 registry 凭据写到浏览器配置。

## 宿主认证集成

默认采用同源 fetch 行为。需要特殊认证时使用现有服务和公开适配接口，核对已安装类型；不要凭空给 `Agent` 添加未声明的 `headers` props。历史、附件和反馈使用的端点也需要独立确认认证。

Cookie 认证核对域、路径、SameSite、Secure 与实际请求携带情况。凭据过期由业务系统重新登录，保留明确错误，不无限自动重试。

## 流式部署

确认代理不把整个事件流缓冲到最后，长任务超时符合业务要求，断线按后端合同取消或恢复。检查首段输出、工具结果、结束和错误事件的顺序。

至少验证有效登录、未登录、无权限、会话过期、网络中断与主动取消。日志保留请求标识和状态码，移除 Cookie、Authorization 与个人数据。
