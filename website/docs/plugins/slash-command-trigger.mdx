# / 快捷命令（slash-command-trigger）

## 功能与效果

<figure className="plugin-preview">

![快捷命令界面](/images/plugins/slash-command-trigger.png)

<figcaption>输入 / 后显示命令候选；指令插入草稿，动作执行项目操作。</figcaption>
</figure>

输入 `/` 打开命令菜单。菜单中的指令会进入草稿供本次发送使用，动作则在选择时执行项目行为；插件已区分这两种流程，无需用户为普通选项自己调用 Composer。

### 选择指令，或执行一个动作

`directive` 模式选中后默认插入命令引用，例如 `:command[总结]{name=summarize}`，用户继续编辑后再发送。它本身不启动 Agent 请求。

<figure className="plugin-preview">

![选中总结对话指令后的 Lexical 草稿](/images/plugins/lexical-composer-input.png)

<figcaption>启用 Lexical 输入时，“/总结对话”显示为草稿内的标签；菜单已关闭，用户可以继续补充问题，再点击发送。</figcaption>
</figure>

`action` 模式默认调用条目的 `execute()`，例如新建会话或打开项目面板；不把这个动作作为指令留在草稿，也不自动写入业务选择数据。默认命令源中的新建会话即属于动作模式。

命令可来自公开 `source`，也可由业务插件通过[会话命令源](./conversation-command-source#随业务插件启停注册命令)注册。服务变化后菜单跟随更新，菜单查询与键盘选择由插件处理。

## 数据来源与显示条件

### 交给 Composer 的数据

<span id="命令携带业务类型"></span>

<span id="example-1"></span>

例如项目提供这个指令：

```json ag-ui
{ "id": "summarize", "label": "总结", "mode": "directive", "data": { "taskType": "summary" } }
```

选中后正文包含 `:command[总结]{name=summarize}`。假设触发器实例 ID 为 `task-command`，Composer 最终适配器读取到：

```json ag-ui
{
  "pluginData": {
    "task-command": [
      {
        "id": "summarize",
        "label": "总结",
        "mode": "directive",
        "data": {
          "taskType": "summary"
        }
      }
    ]
  }
}
```

原始选择快照保留 `id/label/mode` 及实际提供的 `description/disabled/data`，不保存 `execute` 函数。`pluginData[实例ID]` 是数组；多个仍在正文中的引用可同时保留，删除引用就排除其数据。

**默认只发送正文引用，不自动附加结构化外带字段。** 命令业务数据由已有 [Composer `requestAdapter`](./composer#请求适配) 读取并决定发送格式；`slash-command-trigger` 没有局部 `requestAdapter`。命令源服务也不会另外提供一份数据。

例如选中“总结”指令后输入“请总结本次会话”，点击发送后的用户消息为（仅列相关字段）：

```json ag-ui
{
  "messages": [
    {
      "id": "user-1",
      "role": "user",
      "content": ":command[总结]{name=summarize} 请总结本次会话"
    }
  ]
}
```

普通触发器使用其插件实例键；嵌入其他业务插件时使用该实例的 `:command` 子键。动作默认没有上述条目，不能假设每次选择菜单都会产生 `pluginData`。

### 发送、编辑与再次选择

插入不等于发送。正常发送使用当前有效引用快照；重试和工具续答保留原次提交的数据。编辑消息时移除命令引用，便不再携带该引用的数据。单独恢复正文标记只能恢复显示，原始业务 `data` 需随前端历史元数据保留，见 [Composer 的提交与历史规则](./composer#提交后的快照重发与会话切换)。

### 选中后只插入纯文本 {#选中命令后替换为纯文本}

<span id="example-2"></span>

`onSelect` 接管默认指令插入和动作执行。返回值只替换当前 `/` 查询片段；下面插入名称，周围草稿由插件保留，不需要调用方拼接：

```tsx
import type { ComponentProps } from 'react';
import { CanonicalConversationSlashCommandTrigger } from '@za38.03/agent-ui-plugins';

export function PlainCommand(props: ComponentProps<typeof CanonicalConversationSlashCommandTrigger>) {
  return <CanonicalConversationSlashCommandTrigger {...props} onSelect={command => command.label} />;
}
```

非空返回文字会绑定原始选择供 Composer 读取；`null` 移除查询，不记录数据。设置回调后，即使条目原来是 `action`，也不会再自动执行 `execute()`。回调抛错时恢复原查询和选择，不把失败操作当作一次新选择。

## 属性与 API

<span id="属性"></span>

<span id="开发-api"></span>

### API



在 `CanonicalConversationSlashCommandTrigger` 上设置以下属性。

无独立根外观属性。

| 属性 | 类型 | 省略时 / 用途 |
| --- | --- | --- |
| `source?` | [`ConversationSlashCommandSource`](#conversationslashcommandsource) | 从已有命令数据源读取命令列表；缺少时不显示命令候选界面 |
| `onSelect?` | `(command, { text, range }) => string \| null` | 完全替换指令插入和动作执行；见[选中与发送格式](/development/composer-sources#在项目中替换选中行为) |

`mode: 'directive'` 插入序列化指令引用，没有独立草稿文本属性，不自动发送消息。

文案字段见统一 `conversationTriggers` 命名空间。

#### 命令来源与选中后的行为 {#conversationslashcommandsource}

`source.getSnapshot()` 同步返回 `readonly ConversationSlashCommand[]`，`source.subscribe(listener)` 通知菜单重新读取并返回取消订阅函数。异步业务请求由项目数据源执行，完成后更新同一个注册器；普通业务插件动态加入命令见[命令注册器](./conversation-command-source#随业务插件启停注册命令)。

<span id="conversationslashcommand"></span>

| 命令字段 | 类型 | 决定什么 |
| --- | --- | --- |
| `id` / `label` | `string` | 稳定命令身份／菜单展示文字 |
| `description?` | `string` | 可选菜单说明 |
| `disabled?` | `boolean` | 当前命令是否不可选 |
| `mode` | `'directive' \| 'action'` | 插入草稿指令，或立即执行业务动作 |
| `execute` | `() => void \| Promise<void>` | `action` 必需，只有选中后执行；`directive` 不提供此方法 |
| `data?` | `unknown` | 项目自定义的 JSON 业务数据，随原始选中项交给 Composer |

默认情况下，`directive` 插入引用且不发送，`action` 调用 `execute()`。设置 `onSelect` 会接管这两种默认行为，前面的[纯文本插入示例](#选中命令后替换为纯文本)因此不会再执行动作。

<span id="hook"></span>

扩展 `/` 菜单有两个位置：在本组件传入 `source` 提供整份命令，或让其他业务插件通过[命令注册服务](./conversation-command-source#服务)动态加入自己的命令。`onSelect` 决定选中后的插入或动作，见[纯文本插入示例](#选中命令后替换为纯文本)。

命令的业务参数直接放在来源的 `data` 中；[Composer requestAdapter](./composer#请求适配) 统一决定最终请求。未配置 Composer 适配器时只发送正文引用，不自动添加结构化外带字段。其他业务选择也可以通过 [Composer `setData()`](./composer#example-3) 写入本次草稿。
