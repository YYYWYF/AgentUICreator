# 消息输入（composer）

需要在回复期间发送后续问题时，先按[消息排队](/development/message-queue)开启；该教程说明待发送列表、移除、停止和切换会话的行为。

用户可以输入和修改草稿。附件、引用、语音和发送按钮按项目配置组合在这个区域中。

日常调整可以交给 Creator；需要自己写代码时，直接查看[属性](#属性)。

![输入消息（composer）界面示例](/images/plugins/composer.png)

## 启用与使用

在 **Creator 输入框**输入 `/enable composer`，点击下图中的 **「输入消息」**。

![Creator 启用菜单：点击「输入消息」，插件 ID 为 composer](/images/plugins/enable/composer.jpg)

打开已有对话页面，在输入区填写内容并发送。调整输入区时，可要求 Creator 保留附件、引用和发送入口。

## 定制选项

| 可以改什么 | 效果 |
| --- | --- |
| 输入提示 | 修改输入框为空时显示的提示文字。 |
| 输入框高度 | 设置初始行数、最小高度和内边距。 |
| 字数限制 | 限制一条草稿最多可以输入多少字符。 |
| 发送快捷键 | 选择回车发送、Ctrl/Cmd + Enter 发送，或关闭快捷键发送。 |
| 自动进入输入状态 | 决定打开页面时是否自动把光标放到输入框。 |
| 拖入附件 | 允许或禁止把文件拖入输入区。 |
| 按钮和引用的位置 | 调整输入框上方内容、左右按钮和发送按钮的组合。 |

## 需求示例

```text
请修改「输入消息（composer）」：
修改：输入提示改为【请输入你的问题】，初始显示【3】行，发送快捷键改为【Ctrl/Cmd + Enter】。
保留：附件、引用和发送按钮。
```

## 属性

打开项目中的 `plugins/composer/index.tsx`，在已有公开组件调用处设置属性或调整组合。修改外观时，保留文件中读取会话状态、调用服务、显示子插件和注册消息组件的代码。

`?` 表示可选；“省略时”描述当前组件行为。`ReactNode`、`CSSProperties`、`ComponentProps` 等为 React 类型；完整类型以项目实际安装版本为准。

输入组件：`ConversationCanonicalComposer`；类型：`ConversationCanonicalComposerProps`。继承表单原生属性，排除 `children`。

| 属性 | 类型 | 省略时 / 用途 |
| --- | --- | --- |
| `rows?` | `number` | 默认输入框行数，最终默认 `1`；覆盖 `inputProps.rows` |
| `maxLength?` | `number` | 最大长度；覆盖 `inputProps.maxLength` |
| `submitMode?` | `'enter' \| 'ctrlEnter' \| 'none'` | 优先于 `inputProps.submitMode`；最终未设置时底层默认 `enter` |
| `autoFocus?` | `boolean` | 使用所在输入区的自动聚焦设置 |
| `compact?` | `boolean` | 继承表单组件的紧凑模式开关，默认 `false` |
| `inputProps?` | `ConversationComposerInputProps` | 默认输入框属性，见下表 |
| `dropzoneProps?` | `ConversationComposerDropzoneProps` | 附件拖放区属性，类型来自现有 AttachmentDropzone |
| `triggers?` | `ReactNode` | 提及／命令触发器内容 |
| `beforeInput?` | `ReactNode` | 输入框前的内容，例如引用预览 |
| `input?` | `ReactNode` | 替换默认 textarea；自定义输入自行接收其属性 |
| `leadingActions?` | `ReactNode` | 前部操作区 |
| `trailingActions?` | `ReactNode` | 后部操作区 |
| `submitAction?` | `ReactNode` | 提交操作区 |
| `onSubmit?` | `ConversationComposerRootProps['onSubmit']` | 表单提交回调；保留默认发送与等待回复检查 |
| `requestAdapter?` | `ComposerRequestAdapter` | 同步定制最终 AG-UI 请求，见下方请求适配；省略时沿用默认组装 |

`inputProps` 继承自动增高 textarea 的原生属性，包括 `rows`、`maxLength`、`minRows`、`maxRows`、`onChange`、`onKeyDown`、`className`、`style`，另有：

| 嵌套属性 | 类型 | 省略时 / 用途 |
| --- | --- | --- |
| `inputProps.submitMode?` | `'enter' \| 'ctrlEnter' \| 'none'` | 默认 `enter`；`ctrlEnter` 在 macOS 上为 Cmd+Enter |
| `inputProps.cancelOnEscape?` | `boolean` | 默认 `true`，Esc 取消编辑 |
| `inputProps.addAttachmentOnPaste?` | `boolean` | 默认 `true`，粘贴文件时添加附件 |
| `inputProps.asChild?` | `boolean` | 把输入属性传给已有子元素 |
| `inputProps.render?` | `ReactElement` | 自定义输入容器 |
| `inputProps.unstable_focusOnRunStart?` | `boolean` | 实验接口，默认 `true`；运行开始时按底层条件聚焦 |
| `inputProps.unstable_focusOnScrollToBottom?` | `boolean` | 实验接口，默认 `true`；滚动到底部时聚焦 |
| `inputProps.unstable_focusOnThreadSwitched?` | `boolean` | 实验接口，默认 `true`；切换会话时聚焦 |
| `inputProps.unstable_insertNewlineOnTouchEnter?` | `boolean` | 实验接口，默认 `false`；触控主设备的 Enter 插入换行 |

`dropzoneProps` 继承 `div` 原生属性，另公开 `asChild?: boolean`、`render?: ReactElement`、`disabled?: boolean`。当前 Composer 默认通过 `asChild` 把拖放事件交给已有容器处理；`disabled` 与会话禁用状态叠加。它不是另一个上传服务配置入口。

同一位置已经配置子插件时，优先显示该子插件；没有配置时，才使用相应的内容属性。`input` 已替换时，根上的 `rows` 等不会自动配置任意自定义组件。

### 类型查询

可在编辑器中通过公开组件取得完整属性类型：

```ts
import type { ComponentProps } from 'react';
import type { ConversationCanonicalComposer } from '@za38.03/agent-ui-plugins';

type ImplementationProps = ComponentProps<typeof ConversationCanonicalComposer>;
```

具体属性和保留插槽的修改示例见[输入框定制](/development/component-customization)。

默认输入提示、无障碍名称和排队文案统一在 `locales.composer` 修改。原生 `inputProps` 和自定义输入组件继续用于行为与结构定制。 所有语言覆盖均需保持 `en-US` / `zh-CN` 对应。

## 开发 API

### Hook

从用途选择 Hook：

- **修改草稿和写入参数**：`useComposer(name?)` 提供当前输入区的操作与 JSON 草稿数据。
- **响应式读取输入状态**：`useConversationComposer()` 提供输入状态、附件与发送／取消操作。
- **判断是否等待用户处理**：`useConversationComposerAwaitingReply()` 返回是否等待审批或补充输入。
- **读取等待标识**：`useConversationComposerGuardState()` 同时返回 `interruptKey`。
- **适配最终请求**：`useComposerRequestAdapter(adapter)` 为已接管的 Composer 实现注册当前会话唯一的同步请求适配器；普通业务插件使用 `setData`。

具体签名与示例见下方。

从 `@za38.03/agent-ui-plugins` 导入 `useComposer`。它复用当前 Thread 的原生输入区，需要已有 Conversation 上下文；`setData` 还需要 Agent UI 提供的草稿数据上下文。

| 成员 | 参数与返回值 | 用途 |
| --- | --- | --- |
| `subscribe(listener)` | `(() => void) → () => void` | 订阅原生草稿变化，返回取消订阅函数 |
| `setQuote(quote)` | `{ text, messageId } \| undefined → void` | 设置或清除原生引用 |
| `getState()` | 原生 Composer 状态快照 | 读取 `text`、`canSend` 等；此调用自身不订阅变化 |
| `setText(text)` | `string → void` | 修改同一份输入草稿 |
| `send()` | `void` | 通过当前输入区提交草稿 |
| `setData(data, options?)` | `(ComposerData, ComposerDataOptions?) → () => void` | 设置本插件的 JSON 草稿数据 |
| `clearData()` | `void` | 清除当前 Thread 中本调用方拥有的数据；私有引用恢复为公开的 fallback 文本 |

`name?: string` 区分同一插件内的子用途；默认以插件**实例 ID**隔离数据。插件上下文外调用时以 `standalone` 为基础，多个调用方应传不同名称；仍须位于已有 Conversation 内。不同 Thread 的草稿数据分开保存。

`setData` 返回只释放本次写入的函数；后续写入不会被旧清理函数移除。适合建议问题等直接发送动作的清理。

`ComposerData` 是 JSON 值，不能传函数、DOM 或循环对象。无引用的 `setData` 更新本调用方的数据；带引用的数据可保留多项选择。`ComposerDataOptions` 包含：

| 属性 | 类型 | 用途 |
| --- | --- | --- |
| `reference?` | `{ token: string; text: string; fallbackText: string }` | 绑定输入中的引用；删除引用时移除其数据，发送时替换 token |
| `quote?` | `{ text: string; messageId: string }` | 绑定原生引用，取消引用后排除数据 |
| `defaultForwardedProps?` | `Readonly<Record<string, ComposerData>>` | 插件的默认外带字段；同一顶层对象与原字段浅合并，插件字段优先 |
| `defaultTextPrefix?` | `string` | 插件默认加到当前用户正文前的文本 |
| `selection?` | `ComposerData` | 保留原始选择，供最终适配器读取 |
| `includeInRequest?` | `boolean`，默认 `true` | 是否按实例 ID 自动进入外带参数；`false` 仍可由适配器读取，并可显式提供默认组装字段 |

`useConversationComposer(): ConversationComposerController` 响应式提供以下状态与操作：

| 类别 | 成员 |
| --- | --- |
| 草稿 | `text`、`setText(text)` |
| 附件状态 | `attachments`、`attachmentAccept`、`attachmentsEnabled` |
| 可用状态 | `isRunning`、`disabled`、`canSend`、`canCancel` |
| 发送与取消 | `send()`、`cancel()` |
| 附件操作 | `addAttachment(file): Promise<void>`、`removeAttachment(id): Promise<void>` |

它不提供结构化数据写入；这类写入使用 `useComposer`，不要混作同一接口。

### 请求适配

`ComposerRequestAdapter` 的签名为 `(input: ComposerRequestAdapterInput) => RunAgentInput`；`RunAgentInput` 从 `@ag-ui/client` 导入。输入含：

| 字段 | 类型 | 内容 |
| --- | --- | --- |
| `request` | `RunAgentInput` | 已完成默认组装的请求 |
| `pluginData` | `Readonly<Record<string, ComposerData>>` | 按插件实例 ID 或命名子作用域归组的数据 |
| `selections` | `Readonly<Record<string, readonly ComposerData[]>>` | 各调用方保留的原始选择 |

请求参数按以下规则组装：

- **默认位置**：允许发送的插件数据放入 `request.forwardedProps` 的对应调用方键下。没有适配器时，与已有字段同名会报错。
- **配置适配器后**：`request` 保留同名的已有字段，插件数据仍在 `pluginData` 中，由适配器决定如何使用。
- **最终结果**：适配器返回的请求不再合并默认 `forwardedProps`；需要保留原字段时，显式展开。

同一个 Agent 只能注册一个最终适配器。普通应用在已有 Composer JSX 上传 `requestAdapter`，不要在每个业务插件里分别注册；工具续传和中断恢复会对原次提交的数据再次调用它。

```tsx
import {
  ConversationCanonicalComposer, type ComposerRequestAdapter,
} from '@za38.03/agent-ui-plugins';
import type { ComponentProps } from 'react';

const requestAdapter: ComposerRequestAdapter = ({ request, pluginData }) => ({
  ...request,
  forwardedProps: { pluginData },
});

export function ProjectComposer(props: ComponentProps<typeof ConversationCanonicalComposer>) {
  return <ConversationCanonicalComposer {...props} requestAdapter={requestAdapter} />;
}
```

在项目已有的 Composer 入口应用这个属性并保留其组合；不要额外挂载第二个 Composer。若要保留原外带字段，先将 `request.forwardedProps` 作为 `unknown` 检查为对象后再展开。
