# 消息输入（composer）

<figure className="plugin-preview">

![消息输入与发送界面](/images/plugins/composer.png)

<figcaption>在输入框中填写问题，也可以添加附件、使用语音输入，再点击发送。</figcaption>
</figure>

在当前会话中输入文字，根据需要添加附件、引用消息或选择其他内容，准备好后一起发送。

## 准备并发送一条消息

<span id="消息输入与发送"></span>

默认按 Enter 发送，按 Shift+Enter 换行。页面支持添加附件、引用消息等功能时，这些内容会和输入的文字一起发送。可用功能由页面配置决定。

<figure className="plugin-preview">

![界面示例](/images/plugins/add-attachment-action.jpg)

<figcaption>添加附件后，输入框会显示所选文件；你可以移除附件，也可以继续编辑文字。</figcaption>
</figure>

配置附件上传服务时，点击发送才上传并取得文件地址。选择、移除和错误展示沿用当前附件流程，具体服务与输出格式见[附件与 Composer 的联动](./add-attachment-action#与-composer-联动)。

<figure className="plugin-preview">

![消息引用界面](/images/plugins/conversation-quote.png)

<figcaption>选中的消息内容出现在输入区引用预览中；关闭预览即取消本次引用。</figcaption>
</figure>

引用先进入预览，用户可以继续修改问题；删除引用后，这份引用不再随消息发送。默认正文和结构化数据的区别见[引用交给 Composer 的数据](./conversation-quote#交给-composer-的数据)。

## 运行与等待用户操作

普通发送、回车和已有输入区共用提交流程。生成中显示停止入口，当前运行结束后可发送下一条消息。

停止会取消当前运行；工具续传、审批与补充输入沿用原有流程。完整行为见[发送与停止](./submit-action#与-composer-联动)。

等待审批或补充信息时，普通发送受到已有保护，草稿保留；用户继续处理原操作，而不是把普通输入当作审批回答。自定义业务发送入口也应使用下面带保护的草稿控制器。

## 与哪些插件共享输入和发送

每个插件提供的原始数据、默认发送位置和移除规则在它自己的页面说明。这里保留联动入口，避免把各插件的格式混写成一份通用对象：

| 联动入口 | 对当前草稿或请求的作用 |
| --- | --- |
| [@ 提及](./mention-trigger#交给-composer-的数据) | 插入正文引用，保留原始候选数组供最终适配器读取 |
| [/ 快捷命令](./slash-command-trigger#交给-composer-的数据) | 指令模式插入引用；动作模式默认执行动作，不产生选择数据 |
| [命令源](./conversation-command-source#与-composer-联动) | 提供 `/` 菜单数据，选择快照归命令触发器所有 |
| [消息引用](./conversation-quote#交给-composer-的数据) | 默认加 Markdown 引用正文，也可转换为业务 JSON |
| [技能（开发中）](./skills#交给-composer-的数据) | `setData({ id, label })` 保存原始数据，生成项目的 `requestAdapter` 默认映射为 `ctx.skill` |
| [建议问题](./conversation-suggestions#交给-composer-的数据) | 默认发送或填入 prompt，保留原始建议项 |
| [附件](./add-attachment-action#与-composer-联动) | 进入原生附件列表与消息内容，不在插件数据字典中另建记录 |
| [语音](./dictation-action#与-composer-联动) | 按现有能力将识别文字写入正文，不自动产生音频附件 |
| [发送／停止](./submit-action#与-composer-联动) | 提交、取消或为本次发送选择地址，不提供业务数据条目 |
| [Lexical 输入](./lexical-composer-input#与-composer-联动) | 编辑同一份文本与指令标签，不额外生成选择数据 |
| [消息编辑](./lexical-edit-composer#与-composer-联动) | 编辑已有消息，沿用该消息仍有效的选择快照 |
| [会话界面](./conversation-surface#输入区与会话作用域) | 将输入区放进现有会话作用域，提供当前 Thread 与原有插槽组合 |

这些键使用**插件实例 ID**，不一定等于插件 ID；同一类插件可以有多个实例。例如插件 ID 是 `mention-trigger`，页面中的实例 ID 是 `employee-mention`。用户选中“小李”后，Composer 的 `requestAdapter` 收到的选择数据如下：

```json ag-ui
{
  "pluginData": {
    "employee-mention": [
      {
        "id": "u-1",
        "type": "user",
        "label": "小李",
        "data": {
          "employeeId": "E1001"
        }
      }
    ]
  }
}
```

在 `requestAdapter` 回调中，按实例 ID 取值：

```ts
const employees = pluginData['employee-mention'];
// 本次未提交这份数据时为 undefined，组装请求时不添加对应字段。
// 有数据时是上面的候选数组，第一项的 data 为 { employeeId: 'E1001' }。
```

按实际实例 ID `employee-mention` 读取这份候选数组。没有选中项时，该键可以不存在；组装请求时先用 `Object.hasOwn(pluginData, 'employee-mention')` 判断，存在才添加业务字段，不默认补空数组或 `null`。插件未启用和已启用但本次没有选择，都可能没有这个键。

带名称的调用会加上子作用域。例如实例 `order-picker` 内调用 `useComposer('order').setData({ orderId: 'A1001' })`，Composer 用 `pluginData['order-picker:order']` 取到 `{ orderId: 'A1001' }`。嵌在其他插件中的提及入口可能使用 `实例ID:mention`，格式见各插件页。

## Composer 接受的数据与最终请求

输入区中的内容通过两条路径参与发送：

- **原生草稿**：正文、引用和附件由当前会话转换为 `request.messages`。仅文字时 `content` 可以是字符串；带附件时可以是文字和媒体片段组成的数组。
- **插件业务数据**：通过 `setData()` 提交 JSON，最终适配器统一从 `pluginData` 取得它们。所有插件只提交自己要提供的 JSON，不在插件内配置请求适配器或默认外带字段；业务字段由 Composer 的最终适配器映射。

`ComposerData` 支持字符串、有限数值、布尔值、`null`、这些值组成的数组和普通对象。不能放函数、`undefined`、`NaN`、文件对象、DOM、类实例或循环引用；原始 `File` 用附件接口加入。

`requestAdapter` 的返回值必须是完整、符合当前 AG-UI 契约的 `RunAgentInput`，不是一个业务对象片段。下面是仅含文字的一次请求示例：

```json ag-ui
{
  "threadId": "thread-1",
  "runId": "run-1",
  "state": {},
  "messages": [{ "id": "user-1", "role": "user", "content": "请查询这笔订单" }],
  "tools": [],
  "context": [],
  "forwardedProps": { "ctx": { "tenantId": "t-1" } }
}
```

`messages` 还可能包含历史消息、工具调用与工具结果；续答时也需要它们。业务通常展开原有 `request`，只修改约定的字段，保留实际运行 ID、消息关联、工具与状态。

附件片段在[附件页](./add-attachment-action#与-composer-联动)给出；正文引用和业务选择分别见前面的联动入口。它们不会因为设置了最终适配器而自动变成某种固定业务格式。

## 读取本次请求与插件数据 {#请求适配}

回调接收 `{ request, pluginData, sources }`：`request` 已包含正文、附件、引用和页面参数，`pluginData` 提供各插件的选择数据。

Composer 使用回调返回的请求；若页面还配置了 [`beforeRequest`](/development/connect-agent#发送前准备请求)，它会在之后执行。需要先请求业务接口申请 ID 或补充参数时，使用后者。

旧项目若仍读取 `selections`，改为 `pluginData`，并将各输入插件的请求转换集中到 Composer；升级 npm 不会自动修改这些项目文件。

`pluginData` 按插件实例分组。普通 `setData(value)` 保留原值，提及和命令等引用型选择使用数组；没有数据时可省略该键。`sources` 记录对应的插件 ID、实例 ID 和用途名。

例如订单卡片实例 `order-picker` 调用 `useComposer('order').setData({ orderId: 'A1001' })` 后，一次适配器输入可以是：

```json ag-ui
{
  "request": {
    "threadId": "thread-1",
    "runId": "run-1",
    "state": {},
    "messages": [
      {
        "id": "user-1",
        "role": "user",
        "content": "请查询这笔订单"
      }
    ],
    "tools": [],
    "context": [],
    "forwardedProps": {
      "ctx": {
        "tenantId": "t-1"
      }
    }
  },
  "pluginData": {
    "order-picker:order": {
      "orderId": "A1001"
    }
  },
  "sources": {
    "order-picker:order": {
      "pluginId": "order-card",
      "instanceId": "order-picker",
      "name": "order"
    }
  }
}
```

普通 `setData(value)` 不自动写入 `forwardedProps`，业务映射由最终适配器完成；不要从 `forwardedProps` 反推完整选择，也不要把所有 `pluginData` 都当作数组。各插件页提供其实际 JSON 示例。

## 统一组装业务字段

在项目已有 `plugins/composer/index.tsx` 的实现调用处配置一个最终适配器。下面假设 @、/、引用和建议问题的实例 ID 分别为 `employee-mention`、`task-command`、`quote`、`suggestions`，后端约定将它们放入 `forwardedProps.ctx` 的四个字段。

**只有本次提交了对应数据，才添加业务字段。** `Object.hasOwn` 判断的是键是否存在，因此插件明确提交的空数组、`null`、`false`、`0` 或空字符串都保留原值；没有任何相关数据时直接返回已有请求。

```tsx
import type { ComponentProps } from 'react';
import { ConversationComposerPlugin as Implementation } from '@za38.03/agent-ui-plugins/composer';
import type { ComposerRequestAdapter } from '@za38.03/agent-ui-plugins';

function record(value: unknown): Record<string, unknown> {
  return typeof value === 'object' && value !== null && !Array.isArray(value)
    ? (value as Record<string, unknown>) : {};
}

export const requestAdapter: ComposerRequestAdapter = ({ request, pluginData }) => {
  const fields = {
    ...(Object.hasOwn(pluginData, 'employee-mention')
      ? { mentions: pluginData['employee-mention'] } : {}),
    ...(Object.hasOwn(pluginData, 'task-command')
      ? { commands: pluginData['task-command'] } : {}),
    ...(Object.hasOwn(pluginData, 'quote')
      ? { quote: pluginData['quote'] } : {}),
    ...(Object.hasOwn(pluginData, 'suggestions')
      ? { suggestions: pluginData['suggestions'] } : {}),
  };
  if (Object.keys(fields).length === 0) return request;

  const forwardedProps = record(request.forwardedProps);
  return {
    ...request,
    forwardedProps: {
      ...forwardedProps,
      ctx: { ...record(forwardedProps.ctx), ...fields },
    },
  };
};

export function ConversationComposerPlugin(props: ComponentProps<typeof Implementation>) {
  return <Implementation {...props} requestAdapter={requestAdapter} />;
}
```

例如本次只提交了 @ 提及，其他三个插件没有提交数据：

```json ag-ui
{
  "pluginData": {
    "employee-mention": [{ "id": "u-1", "type": "user", "label": "小李", "data": { "employeeId": "E1001" } }]
  }
}
```

假设 Host 已有 `ctx.tenantId`，上例组装的相关请求字段为：

```json ag-ui
{
  "forwardedProps": {
    "ctx": {
      "tenantId": "t-1",
      "mentions": [{ "id": "u-1", "type": "user", "label": "小李", "data": { "employeeId": "E1001" } }]
    }
  }
}
```

本次不会新增 `commands`、`quote`、`suggestions`。若 `pluginData` 是 `{ "suggestions": [] }`，则明确发送 `suggestions: []`；若没有这个键，则不新增该字段。Host 原先提供的字段继续保留。

四个字段名按后端约定调整。返回 `forwardedProps: {}` 可清空 Composer 的外带字段；之后的 `beforeRequest` 仍可继续修改。上例保留正文和附件。

若后端使用标准 AG-UI Context，也可以将 JSON 编码为字符串后追加到已有 Context：

```tsx
import type { ComposerRequestAdapter } from '@za38.03/agent-ui-plugins';

export const addBusinessContext: ComposerRequestAdapter = ({ request, pluginData }) => {
  if (Object.keys(pluginData).length === 0) return request;
  return {
    ...request,
    context: [...request.context, {
      description: 'Selected business data',
      value: JSON.stringify(pluginData),
    }],
  };
};
```

Context 的每项为 `{ description: string, value: string }`。修改 `messages` 时，用户消息的 `content` 可能是字符串或片段数组；保留数组中的图片、文档等片段，不要直接把整个内容数组转换为普通字符串。

插件数据先按实例键分别保存；只有 Composer 的最终适配器决定业务字段的位置、命名和合并方式。未配置映射时，`setData()` 收集的数据不自动进入 `forwardedProps`。

一个 Agent 只配置一个 Composer 请求适配器，同步返回完整请求。返回无效数据或抛错时停止发送。重试和续答也会调用它，因此只在这里转换数据；异步准备使用 [`beforeRequest`](/development/connect-agent#发送前准备请求)。

## 从业务卡片填入问题和参数 {#从订单卡片填入问题并携带订单-id}

<span id="example-3"></span>

下面的按钮位于已有 Agent／Conversation 中的订单卡片插件。问题和按钮文字由项目文案提供，订单 ID 来自业务数据：

```tsx
import { useComposer } from '@za38.03/agent-ui-plugins';

export function AskAboutOrder({ orderId, prompt, label }: {
  orderId: string; prompt: string; label: string;
}) {
  const composer = useComposer('order');
  return <button type="button" onClick={() => {
    composer.setText(prompt);
    composer.setData({ orderId });
  }}>{label}</button>;
}
```

点击会**替换当前正文**并登记该调用方的业务数据，此时不发送。用户仍能修改问题、添加附件，再使用原有发送入口。数据不等于可见标签，`setData()` 不会自行在输入框里绘制订单卡片。

`useComposer('order')` 使用 `插件实例ID:order` 区分数据；不传名称时使用实例 ID。在现有会话内使用，插件外调用时通过名称区分不同用途。

再次 `setData()` 会替换自己的旧值，绑定正文引用时可保留多项选择。`clearData()` 清除自己的数据；`setData()` 返回的清理函数只清除那次写入。

## 让其他插件实时跟随草稿 {#hook}

<span id="取数与联动"></span>

其他插件需要随草稿更新界面时，使用 `useComposer(selector, name?)` 选择所需字段；无参数的 `useComposer()` 或 `useComposer(name)` 返回即时读取与操作句柄，不自动订阅数据：

```tsx
import { useComposer } from '@za38.03/agent-ui-plugins';

export function DraftSummary({ format }: {
  format: (characters: number, attachments: number) => string;
}) {
  const characters = useComposer(state => state.text.length);
  const attachments = useComposer(state => state.attachments.length);
  return <output>{format(characters, attachments)}</output>;
}
```

`format` 来自项目语言层。只有选中的字数或附件数量变化时才因此重新渲染；这里的 `attachments` 是当前草稿附件，包含 `id`、`name` 和附件状态，不是已经转换好的 AG-UI 媒体片段。

确实需要完整快照的响应式展示时，显式选择整个快照。事件回调中使用无参数句柄的 `getSnapshot()` 或 `getState()` 即时读取：

```tsx
import type { ReactNode } from 'react';
import { useComposer } from '@za38.03/agent-ui-plugins';

export function DraftPreview({ render }: {
  render: (value: { text: string; attachmentCount: number; quoteText: string | undefined }) => ReactNode;
}) {
  const draft = useComposer(state => state);
  return <>{render({
    text: draft.text,
    attachmentCount: draft.attachments.length,
    quoteText: draft.quote?.text,
  })}</>;
}
```

最终适配器的 `pluginData` 对应本次提交的快照；需要多个插件实时共享“选中订单”“当前筛选条件”时，使用[共享业务服务](/development/plugin-interaction#插件之间共享选择或结果)，再由拥有选择的插件提交发送数据。

Hook 随当前会话重新绑定；保留的旧句柄仍绑定原 Thread。长时间保存句柄的业务回调要明确其归属，不能把旧句柄当作自动指向当前会话的全局对象。

## 自定义发送入口并保留运行保护 {#实时显示草稿字数定制发送与停止操作}

<span id="example-4"></span>

只改样式时直接定制[发送／停止插件](./submit-action)。确需自己组合操作区时，继续读取当前控制器与等待用户操作状态：

```tsx
import { useLocale, useComposer } from '@za38.03/agent-ui-plugins';

export function DraftActions({ formatCount }: { formatCount: (count: number) => string }) {
  const composer = useComposer();
  const textLength = useComposer(state => state.text.length);
  const awaitingReply = useComposer(state => state.awaitingReply);
  const disabled = useComposer(state => state.disabled);
  const canSend = useComposer(state => state.canSend);
  const canCancel = useComposer(state => state.canCancel);
  const messages = useLocale('composer');
  return <div>
    <output>{formatCount(textLength)}</output>
    {awaitingReply && <p role="status">{messages.awaitingReply}</p>}
    <button type="button"
      disabled={disabled || !canSend || awaitingReply}
      onClick={() => composer.send()}>
      {messages.send}
    </button>
    <button type="button" disabled={!canCancel}
      onClick={() => composer.cancel()}>{messages.stop}</button>
  </div>;
}
```

`canSend` 已结合草稿准备情况和运行状态，但它本身不表示等待审批保护已经解除；统一的 `send()` 会再执行该保护。这个方法返回 `void`，不是业务 HTTP 保存回执。

`addAttachment(file)` 与 `removeAttachment(id)` 返回 Promise，调用方处理失败；前者走当前附件准备与上传配置，后者按 ID 操作草稿。它们不会把文件登记成一个 `pluginData` 条目。

## 提交后的快照、重发与会话切换

提交时固定本次数据；附件准备、工具续传或中断恢复期间，后续草稿的修改不改变原次提交。已接受提交后清理本次待发送数据，不让普通下一条消息自动继承业务选择。

编辑已有消息时，根据该消息仍存在的引用重新组装；移除引用后不再携带其选择。重试与续答读取原次消息的快照，最终适配器仍可能再次执行。

各会话的草稿与队列分开，技能、引用的清理规则见各插件页。刷新后，正文标记可恢复标签；若还需恢复原始 `data`，历史服务需同时保存选择数据。

## API

<span id="属性"></span>
<span id="开发-api"></span>

项目已有入口使用 `@za38.03/agent-ui-plugins/composer` 的 `ConversationComposerPlugin`；组合组件 `ConversationCanonicalComposer` 使用同一组输入属性。

继承表单原生属性，排除 `children`。

| 属性 | 类型 | 省略时 / 用途 |
| --- | --- | --- |
| `rows?` | `number` | 默认输入框行数，最终默认 `1` |
| `maxLength?` | `number` | 最大长度 |
| `submitMode?` | `'enter' \| 'ctrlEnter' \| 'none'` | 默认 `enter`；`ctrlEnter` 在 macOS 上为 Cmd+Enter |
| `autoFocus?` | `boolean` | 使用所在输入区的自动聚焦设置 |
| `compact?` | `boolean` | 继承表单组件的紧凑模式开关，默认 `false` |
| `inputProps?` | `Omit<ConversationComposerInputProps, 'rows' \| 'maxLength' \| 'submitMode' \| 'autoFocus' \| 'children' \| 'value' \| 'defaultValue'>` | 默认输入框的其他属性，见下表 |
| `dropzoneProps?` | `Omit<ConversationComposerDropzoneProps, 'children'>` | 附件拖放区属性，类型来自现有 AttachmentDropzone |
| `triggers?` | `ReactNode` | 输入框上方的内容 |
| `beforeInput?` | `ReactNode` | 输入框前的内容，例如引用预览 |
| `input?` | `ReactNode` | 替换默认 textarea；自定义输入自行接收其属性 |
| `leadingActions?` | `ReactNode` | 前部操作区 |
| `trailingActions?` | `ReactNode` | 后部操作区 |
| `submitAction?` | `ReactNode` | 提交操作区 |
| `onSubmit?` | `ConversationComposerRootProps['onSubmit']` | 表单提交回调；保留默认发送与等待回复检查 |
| `requestAdapter?` | `ComposerRequestAdapter` | 同步定制最终 AG-UI 请求，见请求适配；省略时沿用默认组装 |

`inputProps` 支持输入区的 `minRows`、`maxRows`、`onChange`、`onKeyDown`、`className`、`style` 等属性。`rows`、`maxLength`、`submitMode` 和 `autoFocus` 只在根属性设置，输入值由会话管理；不提供测量缓存与实验接口。另有：

| 嵌套属性 | 类型 | 省略时 / 用途 |
| --- | --- | --- |
| `inputProps.cancelOnEscape?` | `boolean` | 默认 `true`，Esc 取消编辑 |
| `inputProps.addAttachmentOnPaste?` | `boolean` | 默认 `true`，粘贴文件时添加附件 |
| `inputProps.onHeightChange?` | `(height: number, meta: { rowHeight: number }) => void` | 高度变化时通知，单位为像素；`rowHeight` 为单行测量高度，可用于同步项目外层布局 |
| `inputProps.asChild?` | `boolean` | 把输入属性传给已有子元素 |
| `inputProps.render?` | `ReactElement` | 自定义输入容器 |

`dropzoneProps` 继承 `div` 原生属性，并公开：

- `asChild?: boolean`：把拖放事件交给已有容器；当前 Composer 默认使用这种方式。
- `render?: ReactElement`：自定义渲染元素。
- `disabled?: boolean`：禁用状态与当前会话条件叠加。

上传服务在项目服务配置中接入，不通过 `dropzoneProps` 配置。

单独组合 `ConversationComposerTextareaInput` 时，上述输入属性直接传给该组件，完整属性类型同样使用 `ConversationComposerInputProps` 查询。

同一位置已经配置子插件时，优先显示该子插件；没有配置时，才使用相应的内容属性。`input` 已替换时，根上的 `rows` 等不会自动配置任意自定义组件。

具体属性和保留插槽的修改示例见[输入框定制](/development/component-customization)。

默认输入提示和无障碍名称统一在 `locales.composer` 修改。原生 `inputProps` 和自定义输入组件继续用于行为与结构定制。 所有语言覆盖均需保持 `en-US` / `zh-CN` 对应。

### 响应式草稿控制器

<span id="写入与订阅原生草稿"></span>

Composer 的输入数据、引用转换和最终请求适配由 Plugins 提供。标准项目通过 `createDefaultAgentUIPresentation()` 自动接入；手动使用底层 `ConversationRuntimeProvider` 时，传入 `inputControllerFactory={createComposerInputController}`，其中 `createComposerInputController` 从 `@za38.03/agent-ui-plugins` 导入。未接入时，底层 Runtime 只负责原生会话运行，不创建这些输入能力。

从 `@za38.03/agent-ui-plugins` 或 `/composer-support` 导入 `useComposer(name?)`，返回 `ComposerController`。传入 selector 时返回选中的 `ComposerState` 字段；无 selector 时返回同一份草稿的读取与操作句柄。`setData` 需要 Agent UI 提供的草稿数据上下文。

句柄和方法在同一 Thread、调用方作用域内保持稳定。无 selector 时不自动订阅草稿或运行状态。`useComposer(state => state.text, name?)` 按 `Object.is` 比较选中值；事件回调中用 `getSnapshot()` / `getState()` 读取最新快照，手动订阅用 `subscribe()` 并清理。selector 应返回具体值或稳定引用。

| 状态 | 类型 | 用途 |
| --- | --- | --- |
| `text` | `string` | 当前草稿正文 |
| `attachments` | `readonly ComposerAttachment[]` | 当前草稿附件，包含 `id`、`name` 和状态 |
| `quote` | `{ text, messageId } \| undefined` | 当前引用 |
| `data` | `Readonly<Record<string, ComposerData>>` | 已收集的发送草稿数据，按插件实例隔离；领域 UI 状态由对应 Service 管理 |
| `attachmentAccept` | `string` | 当前接受的文件类型，可传给文件输入的 `accept` |
| `attachmentsEnabled` | `boolean` | 当前 Thread 是否支持附件 |
| `isRunning` | `boolean` | 当前 Thread 是否正在运行 |
| `disabled` | `boolean` | 当前输入是否因会话禁用或语音输入状态而禁用 |
| `canSend` | `boolean` | 草稿是否就绪且当前运行／队列允许发送；不包含等待审批检查 |
| `canCancel` | `boolean` | 当前 Composer 是否允许取消 |
| `awaitingReply` | `boolean` | 当前是否等待用户回答、确认或审批；由 `send()` 执行最终保护 |

| 成员 | 参数与返回值 | 用途 |
| --- | --- | --- |
| `subscribe(listener)` | `(() => void) → () => void` | 订阅草稿、收集的数据和运行状态，返回取消订阅函数 |
| `setQuote(quote)` | `{ text, messageId } \| undefined → void` | 设置或清除原生引用 |
| `getSnapshot()` / `getState()` | `ComposerState` | 读取同一份状态快照，保留原生提交状态等详细字段 |
| `setText(text)` | `string → void` | 修改同一份输入草稿 |
| `send()` | `() → void` | 检查等待回复状态后提交草稿 |
| `cancel()` | `() → void` | 取消当前运行 |
| `addAttachment(file)` | `(File) → Promise<void>` | 将浏览器文件加入草稿；上传仍使用项目附件服务，调用方处理异步失败 |
| `removeAttachment(id)` | `(string) → Promise<void>` | 按附件 ID 移除，调用方处理异步失败 |
| `setData(data, options?)` | `(ComposerData, ComposerDataOptions?) → () => void` | 设置本插件的 JSON 草稿数据 |
| `clearData()` | `() → void` | 清除本调用方的数据，其他插件和原生正文不受影响 |
| `setRunConfig(config)` | 原生 `runConfig → void` | 设置原生运行配置，保留 Composer 管理的提交快照 |

`name?: string` 区分同一插件内的子用途；默认以插件**实例 ID**隔离数据。插件上下文外调用时以 `standalone` 为基础，多个调用方应传不同名称；仍须位于已有 Conversation 内。不同 Thread 的草稿数据分开保存。跨插件 UI 状态通过 Service 共享；`setData(value)` 只收集发送数据并自动记录来源，不接受共享 `key` 或业务生命周期配置。

`setData` 返回只释放本次写入的函数；后续写入不会被旧清理函数移除。适合建议问题等直接发送动作的清理。

`ComposerData` 是 JSON 值，不能传函数、DOM 或循环对象。无引用的 `setData` 更新本调用方的数据；带引用的数据可保留多项选择。`ComposerDataOptions` 只负责将数据绑定到正文引用或原生引用的生命周期：

| 属性 | 类型 | 用途 |
| --- | --- | --- |
| `reference?` | `{ token: string; text: string; fallbackText: string }` | 绑定输入中的引用；删除引用时移除其数据，发送时替换 token |
| `quote?` | `{ text: string; messageId: string }` | 绑定原生引用，取消引用后排除数据 |

### 等待审批与补充输入

使用 `useComposer(state => state.awaitingReply)` 订阅等待状态。为 `true` 时，可像[上例](#example-4)一样禁用普通发送并显示 `locales.composer.awaitingReply`，让用户先处理原审批或补充问题。`send()` 始终执行等待回复保护。

高级定制可从 `composer.getState()` 同时读取 `awaitingReply` 和 `interruptKey`。后者是当前待处理内容的不透明标识，无需解析；与等待状态一起用于重置或去重自定义提示。未等待回复时，`interruptKey` 为空字符串。这些字段的变化也会通知 `composer.subscribe()` 的订阅者。

这些状态由已有 Host 提供。普通业务插件直接读取；`ConversationComposerGuardProvider` 用于手动集成时传入已有中断状态，它本身不检测 Agent 是否暂停。

### 最终请求适配器

<span id="composerrequestadapterinput"></span>

`ComposerRequestAdapter`、`ComposerRequestAdapterInput`、`ComposerDataSource`、`ComposerData` 与 `ComposerDataOptions` 从 `@za38.03/agent-ui-plugins` 导入。`RunAgentInput` 从 `@ag-ui/client` 导入。

| 字段 | 类型 | 内容 |
| --- | --- | --- |
| `request` | `RunAgentInput` | 已完成默认组装的请求；展开后修改约定字段 |
| `pluginData` | `Readonly<Record<string, ComposerData>>` | 按实例或命名子作用域归组的有效数据 |
| `sources` | `Readonly<Record<string, ComposerDataSource>>` | 自动记录的插件 ID、实例 ID 和可选用途名；插件上下文外不伪造插件身份 |

`ComposerRequestAdapter = (input: ComposerRequestAdapterInput) => RunAgentInput`。返回完整同步结果，不返回 Promise 或请求片段。

最终适配器只从 Composer 组件的 `requestAdapter` 属性传入，由组件内部负责注册、更新和卸载清理；同一 Agent 只注册一个最终适配器。`useComposer(name?)` 接受可选的数据作用域名称，负责读取状态和操作草稿。

### 最终请求的主要字段

下面对应前面的完整 JSON 示例。已有运行提供这些字段；适配器展开原请求后修改业务约定，避免重新生成运行和消息身份。

| 字段 | 数据格式 | 使用方式 |
| --- | --- | --- |
| `threadId` / `runId` | `string` | 当前会话与本次运行身份，沿用原请求 |
| `messages` | `Message[]` | 保留历史、用户消息、工具调用及结果；用户 `content` 可为字符串或内容片段数组 |
| `state` | JSON | 当前 Agent 状态，沿用原请求中的实际结构 |
| `tools` | `Tool[]` | 当前运行可用工具声明，通常保留原值 |
| `context` | `{ description: string; value: string }[]` | 追加上下文时把业务 JSON 编码为 `value` 字符串 |
| `forwardedProps` | JSON | 后端约定的外带数据，可由最终适配器重新组织 |

其他由当前协议或运行提供的字段也通过 `...request` 保留。最终结果须符合项目实际安装版本的 `RunAgentInput`，不能只返回这张表中的一部分。
