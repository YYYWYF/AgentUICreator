# 工具结果（tool-result）

工具返回文本、图片、音频、视频或文档时，按内容顺序展示文本、图片预览、播放器和文件下载入口。图片、播放器和文件卡片复用 assistant-ui 的现有组件与 Agent UI 主题。

![同一次工具调用中的文本、图片、音频、视频和文档](/images/plugins/tool-result.png)

## 启用与使用

工作台、悬浮助手和嵌入式助手的新建项目默认启用 `tool-result`。它保留工具参数、错误提示和审批操作，并展示工具返回的多模态内容。

如果现有项目仍使用 `tool-fallback`，可以向 Creator 描述：

```text
请把对话的工具调用详情替换为 tool-result，自动展示工具返回的图片、音频、视频和文档。
保留工具参数、错误提示和审批操作。
```

本插件放在 `conversation-surface` 的 `toolFallback` 渲染位置；该位置只容纳一个插件。如果已有 `tool-fallback`，需要替换该位置的插件。已有项目的启用状态以实际配置为准。已注册的专用工具界面继续优先。

模板 JSON 中的对应组合如下，合并到现有 `conversation-surface` 实例的 `slots` 中：

```json
{
  "toolFallback": [
    { "pluginId": "tool-result" }
  ]
}
```

后端通过 AG-UI `TOOL_CALL_RESULT.content` 返回内容数组，例如：

```json
{
  "type": "TOOL_CALL_RESULT",
  "messageId": "result-1",
  "toolCallId": "call-1",
  "content": [
    { "type": "text", "text": "报告已生成。" },
    {
      "type": "image",
      "source": {
        "type": "url",
        "value": "https://example.com/chart.png",
        "mimeType": "image/png"
      }
    },
    {
      "type": "document",
      "source": {
        "type": "url",
        "value": "https://example.com/report.pdf",
        "mimeType": "application/pdf"
      },
      "metadata": { "filename": "report.pdf" }
    }
  ]
}
```

`audio` 和 `video` 使用相同的 `source` 结构。音视频由用户点击播放，不自动播放，暂不提供下载入口；视频原生控件设置了隐藏下载项。文档保留文件卡片和下载入口，不内嵌执行文档内容。普通字符串、业务 JSON 或不符合内容数组结构的结果沿用原始结果展示。

`source.type` 为 `url` 时使用可访问的 HTTP/HTTPS 或 Blob URL；为 `data` 时需要 Base64 数据和 MIME 类型。为 `file` 时，`value` 是提供方文件标识，需要项目提供文件解析服务，组件不会把标识当作网址请求。媒体地址仍需满足项目的鉴权和浏览器访问条件。

## 显示条件与数据来源

**Agent 服务接入：**先发送[通用工具事件](./ag-ui-data#通用工具事件)中的 `TOOL_CALL_START`、`TOOL_CALL_ARGS`、`TOOL_CALL_END`，建立 `toolCallId: "call-1"` 的调用，再发送上面的 `TOOL_CALL_RESULT`。内容数组及其 `source` 格式见[启用与使用](#启用与使用)。仅发送图片 URL 或插件 ID 不会创建多模态工具结果。

本插件与 `tool-fallback` 使用同一语义位置，有同名专用 Tool UI 时专用展示优先。审批区默认可用，同时支持[旧版 CUSTOM `on_interrupt`](./tool-fallback#旧版格式custom-on_interrupt) 和[新版 `RUN_FINISHED` interrupt](./tool-fallback#新版格式run_finished-interrupt)：两者读取相同的 `action_requests`、`review_configs`，显示「允许」「拒绝」按钮。审批要求由事件表达，不放在媒体内容中。

Mock 中的 `approval-legacy` 和 `approval-resume` 分别演示两种格式；新建项目无需另启用审批插件。若同一轮收到两种格式，只显示一组审批按钮，并通过新版 `resume[]` 提交。完整事件结构和回传字段见[审批数据接入](./tool-fallback#显示条件与数据来源)。

## 属性

项目应用层的 `plugins/tool-result/index.tsx` 引用公开的 `ConversationToolResultPlugin`，继续传入已有的 `tool` 数据并保留子插件渲染调用，通过 React 属性定制展示，无需接管官方源码。

`?` 表示可选；“省略时”描述当前组件行为。`ReactNode`、`CSSProperties`、`ComponentProps` 等为 React 类型；完整类型以项目实际安装版本为准。

插件入口：`ConversationToolResultPlugin`；展示组件：`ConversationToolResult`；类型：`ConversationToolResultProps`。入口接收下表属性及下列 `ToolFallbackPresentationProps`，包括基础外观属性。

| 属性 | 类型 | 省略时 / 用途 |
| --- | --- | --- |
| `tool?` | `ConversationToolResultProps` | 插件入口工具上下文，缺少时不渲染；独立展示组件直接接收工具上下文 |
| `resultOnly?` | `boolean` | 默认不启用；设为 `true` 直接展示结果内容，省略整个工具详情／审批界面，与是否已有结果无关 |
| `resolveFile?` | [`(source: Extract<ToolResultSource, { type: 'file' }>, options: { signal: AbortSignal }) => string \| Promise<string>`](#toolresultsource) | 将文件引用解析为可呈现 URL，支持取消 |
| `renderPart?` | [`(part: ToolResultPart, index: number, defaultContent: ReactNode) => ReactNode`](#toolresultpart) | 自定义每个结果片段，可复用默认内容 |

工具结果使用 `tool.result` 或展示组件的 `result`，不是给插件入口另传一份结果。识别为多模态片段数组时，外层组件分别显示工具详情和结果，内部会覆盖 `renderResult` 以避免重复结果；此时使用 `renderPart` 定制内容。非片段数组使用默认工具结果回退，不调用 `renderPart`。`resultOnly` 会省略工具卡片，包括审批区，使用时保留业务所需的交互入口。

独立内容组件 `ConversationToolResultContent` 接受 `ToolResultContentProps`：必需的 `result: unknown`，以及同上 `resolveFile?`、`renderPart?`。

文件来源未提供 `resolveFile` 时显示不可用提示；工具结果整体还支持默认文本／结构化回退。

### 当前工具调用的数据与操作

这些数据和方法由现有会话传入，类型为 `ConversationToolCallProps`。`toolCallId`、`toolName`、`args`、`status` 是必需字段，其余已列出的字段可选；修改展示时保留原有传参。

| 属性 | 类型 | 用途 |
| --- | --- | --- |
| `type?` | `'tool-call'` | 消息片段类型 |
| `toolCallId` | `string` | 工具调用 ID |
| `toolName` | `string` | 工具名称 |
| `args` | `unknown` | 解析后的输入参数 |
| `argsText?` | `string` | 输入参数的文本形式 |
| `result?` | `unknown` | 工具结果 |
| `messages?` | `readonly ConversationMessage[]` | 关联的嵌套消息 |
| `isError?` | `boolean` | 结果是否为错误 |
| `status` | [`ConversationToolCallStatus`](#conversationtoolcallstatus) | 工具当前状态：运行中、已完成、未完成或等待用户操作 |
| `addResult?` | `(result: unknown) => void` | 提交前端工具结果 |
| `resumeInterrupt?` | `(payload: unknown) => Promise<void>` | 提交恢复数据，让暂停的任务继续执行 |
| `decisionRequest?` | [`ConversationCommandDecisionRequest`](#conversationcommanddecisionrequest) | 运行环境提供的操作确认请求 |
| `submitDecision?` | `(decisionType: string) => Promise<void>` | 提交后端支持的决定 |

该类型允许传入额外字段，但字段是否生效取决于组件实现，不能据此添加任意配置项。

在本插件入口中，上述数据和方法放在 `tool` 对象里；单独使用展示组件时直接传入这些字段。

| 属性 | 类型 | 用途 |

| `approval?` | `ConversationToolFallbackProps['approval']` | 审批请求 |
| `respondToApproval?` | `ConversationToolFallbackProps['respondToApproval']` | 提交审批回答 |

### 文件名和提示文案

文件名可通过内容块的 `metadata.filename` 提供。这是展示约定，不影响 AG-UI 的字段和消息结构。新文案使用 Agent UI 的统一 locale；文件无法解析时显示可本地化的状态提示。


### 类型说明

#### ToolResultPart

一个工具结果片段，共同字段 `id` 和 `metadata` 均可选；按 `type` 区分文本、图片、音频、视频和文档。

```ts
type ToolResultPart = { id?: string; metadata?: unknown } & (
  | { type: 'text'; text: string }
  | { type: 'image' | 'audio' | 'video' | 'document'; source: ToolResultSource }
);
```

文本片段必需 `text`，媒体片段必需 [`ToolResultSource`](#toolresultsource)。`metadata` 可放文件名等展示信息。

#### ToolResultSource

```ts
type ToolResultSource =
  | { type: 'url'; value: string; mimeType?: string }
  | { type: 'data'; value: string; mimeType: string }
  | { type: 'file'; value: string; provider?: string; mimeType?: string };
```

`value` 分别为 URL、Base64 内容或提供方文件标识。`mimeType` 是 MIME 类型，Base64 来源必须提供；`provider` 是可选的文件提供方标识。文件来源需要项目通过 `resolveFile` 解析为 URL。

#### ConversationToolCallStatus

按 `type` 区分工具状态：运行中、已完成、未完成和等待用户操作。

```ts
type ConversationToolCallStatus =
  | { type: 'running' }
  | { type: 'complete' }
  | { type: 'incomplete'; reason?: string; error?: unknown }
  | { type: 'requires-action'; reason?: string };
```

`reason` 是可选原因，`error` 是未完成时的可选错误详情。

#### ConversationCommandDecisionRequest

运行环境提供的操作确认请求。

```ts
interface ConversationCommandDecisionRequest {
  allowedDecisions: readonly string[]; // 后端允许提交的决定标识
  description?: string; // 请求说明
}
```

提交决定时使用 `allowedDecisions` 中的原始标识。

import type { ComponentProps } from 'react';
