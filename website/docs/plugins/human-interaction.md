# 人机交互与操作确认

让 Agent 在需要用户作决定或补充信息时，**先停下来提问，再根据用户的选择继续处理**。

例如，Agent 可以先问「允许删除这些临时文件吗？」，也可以问「首页要用哪种布局？」。用户在对话中的卡片上确认或回答，不用猜应该在聊天框里输入什么。

## 执行前确认

Agent 准备执行需要确认的操作时，卡片会列出操作内容和参数，并显示「允许」「拒绝」按钮。

下图中，Agent 请求清理 `dist/` 和 `.cache/`。用户先检查将处理哪些目录，再决定是否允许这次操作。

![执行前展示操作内容，并让用户允许或拒绝](/images/plugins/tool-fallback-approval.jpg)

- **允许**：同意卡片中的这次操作，Agent 按业务约定继续执行。
- **拒绝**：不同意这次操作，Agent 收到拒绝结果后处理后续流程。
- **取消**：若项目提供取消入口，可结束当前交互；它与明确拒绝是不同的结果。

点击按钮后，要等待提交结果和会话状态更新。卡片上的确认只代表用户的选择，最终是否执行成功仍由实际业务结果决定。

## 选项与信息补充

当 Agent 还缺少信息时，可以在对话中显示问题，让用户选择答案或填写文字。

| 问题形式 | 适用场景 | 用户操作 |
| --- | --- | --- |
| 单选 | 选择一种布局、一个处理方案 | 按卡片提示选择；有些单选会在选中后直接提交。 |
| 多选 | 选择多个需要处理的范围 | 勾选允许数量的选项，再提交。 |
| 文字回答 | 补充名称、需求说明等信息 | 按要求填写，再提交。 |

具体出现哪些问题、是否必填、允许选几项，由 Agent 和项目的人机交互配置决定。

下图中，Agent 先询问用户偏好的首页布局，给出「数据总览」「侧边导航」两个选项。这个单选示例在点击选项后直接提交。

![Agent 询问布局偏好，用户点击选项即可回答](/images/plugins/human-interaction-question.png)

用户点击「数据总览」后，答案交给对应的这次提问，Agent 随后继续回复：

![用户提交布局选择后，Agent 按选择继续回答](/images/plugins/human-interaction-answer.png)

普通聊天框中的新消息不一定能代替问题卡片的答案。需要回答卡片上的问题时，**使用卡片自己的选择和提交入口**。

## 项目接入

三种新建项目模板默认启用 [`tool-result`](/plugins/tool-result)，已包含操作确认区。后端发送[旧版 CUSTOM `ON_INTERRUPT` 或新版标准 interrupt](/plugins/tool-fallback#显示条件与数据来源)，即可在匹配的工具卡片上显示「允许」「拒绝」。若项目已调整过工具展示，检查当前 `toolFallback` 位置是否仍保留审批入口。

在 Mock 中选择 `approval-legacy` 或 `approval-resume`，分别检查旧版、新版格式。两种格式共用同一审批区，不是两个需要分别开启的插件。

问题卡片使用正式的 [`ask-user-question`](/plugins/ask-user-question) 插件。通过 `/enable ask-user-question` 添加并启用，再接入业务服务的提问、答案提交和继续处理能力；只启用工具详情不会自动出现问题卡片。

可以把下面的需求发给 Creator：

> 在当前项目中接入人机交互：操作需要确认时展示具体内容与允许、拒绝按钮；Agent 缺少信息时展示问题卡片。先检查已有审批和问答能力，以及答案提交后继续处理的服务，再保留现有聊天界面完成接入。

接入时分别检查：确认和拒绝是否交给正确的操作、答案是否关联到正确的问题、提交后 Agent 是否按结果继续，以及提交失败时是否能重试。

## 历史交互记录

已完成的问题应显示原来的回答或决定，而不是重新执行。重新进入旧会话后，能否继续回答未完成的问题，取决于业务服务是否仍支持恢复这次交互；过期时应重新发起。
