# 添加附件（add-attachment-action）

在输入区添加草稿附件，配合 附件模型展示准备和移除。

## 界面与功能

输入区出现附件入口，选中文件后显示文件名和准备状态，发送前可以移除。

![添加附件（add-attachment-action）界面示例](/images/plugins/add-attachment-action.png)

截图来源：[assistant-ui 上游示例](https://www.assistant-ui.com/elements/attachment)。用于展示对应组件；本项目的样式与组合以实际工程为准。

## 如何启用和使用

在已创建的工程中启用此 Plugin，放到当前组合支持的位置。可以请 Creator 按下方示例调整；先保留已有页面和其他功能，再检查预览效果。

当前官方预设：在工作台、悬浮式、嵌入式中启用。已有项目可能已经定制，以实际页面为准。

可以把下面的需求发给 Creator：

> 在当前工程中配置「添加附件」，保留已有布局和其他功能。先检查所需服务是否可用，完成后说明改了哪里、怎样验证。

## 使用前提

需要宿主提供上传与文件处理服务。类型、大小、鉴权和上传策略由业务配置，失败的附件应可移除。

## 属性

优先在项目已有 Plugin 应用文件中设置参数；不需要为了改外观复制官方实现。

| 参数 | 用途 |
| --- | --- |
| `style` | 局部尺寸或样式。 |
| `disabled` | 按业务条件限制交互。 |
| `className` | 沿用工程样式命名设置外观。 |
| `children` | 替换或补充组件内容。 |
| `onClick` | 自定义点击反馈，保留原有默认动作。 |
| `actionProps` | 定制对应区域的 DOM、样式或交互参数。 |

## 验证结果

在当前项目检查正常、不可用、失败和取消中与此功能相关的状态。涉及附件、语音、登录、历史和恢复时，分别测试实际业务服务；使用 Mock 时注明它是演示数据。

如果只通过类型检查或构建，仍需在页面验证。失败时查看具体提示，不直接清空工程或覆盖已有定制。
