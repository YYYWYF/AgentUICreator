# 在输入框显示 @ 与 / 标签（lexical-composer-input）

把输入框中已选择的 @ 对象和 / 指令显示成独立标签，便于与普通文字区分。

## 界面与功能

用户仍然可以正常输入文字、移动光标；引用对象和指令各自显示为一个完整标签，删除时按整个标签处理。

下图中，「@产品说明文档」是已选中的引用对象，「/总结对话」是已选中的指令。它们会作为完整标签保留在草稿中，与旁边的普通文字区分开。

![在输入框显示 @ 与 / 标签（lexical-composer-input）界面示例](/images/plugins/lexical-composer-input.png)

## 如何启用和使用

在已创建的工程中启用此 Plugin，放到当前组合支持的位置。可以请 Creator 按下方示例调整；先保留已有页面和其他功能，再检查预览效果。

当前官方预设：未默认加入三种形态，需要按项目需求启用。已有项目可能已经定制，以实际页面为准。

可以把下面的需求发给 Creator：

> 在当前工程中配置「在输入框显示 @ 与 / 标签」，保留已有布局和其他功能。先检查所需服务是否可用，完成后说明改了哪里、怎样验证。

## 使用前提

这是可选输入实现，需要对应编辑器依赖。启用后检查输入法、粘贴和键盘操作，不能改变既有提及身份。

## 属性

优先在项目已有 Plugin 应用文件中设置参数；不需要为了改外观复制官方实现。

| 参数 | 用途 |
| --- | --- |
| `style` | 局部尺寸或样式。 |
| `className` | 沿用工程样式命名设置外观。 |
| `onClick` | 自定义点击反馈，保留原有默认动作。 |
| `children` | 替换或补充组件内容。 |

## 验证结果

在当前项目检查正常、不可用、失败和取消中与此功能相关的状态。涉及附件、语音、登录、历史和恢复时，分别测试实际业务服务；使用 Mock 时注明它是演示数据。

如果只通过类型检查或构建，仍需在页面验证。失败时查看具体提示，不直接清空工程或覆盖已有定制。
