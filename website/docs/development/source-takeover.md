# 源码接管与更新参考

修改文件、组件和本地实现的连贯步骤，统一见[手动修改插件：样式与业务逻辑](./component-customization)。本页用于核对接管后的维护范围。

| 内容 | 默认来源 | 项目如何维护 |
| --- | --- | --- |
| 应用入口、props、组合、业务回调 | 项目 `plugins/<id>/index.tsx` 等 | 普通项目编辑，无需接管；后续保留 |
| 官方实现 | npm 包 | 公开接口不足且用户明确同意后，提取项目实际安装版本 |
| 已接管实现 | 项目插件的 `source/` 目录 | 在适配层修改，原始参考源码与来源记录用于后续同步 |
| 布局、外壳和业务连接 | 项目文件 | 继续由项目维护，源码同步保留这些文件 |

## 接管与更新边界

首次接管时，Creator 会展示具体插件、当前版本、文件与影响范围，确认后将实现提取到项目。成功接管后，可继续编辑该插件的项目文件；接管其他插件时，再分别确认对应计划。

在 Creator 输入 `/takeover`，选择项目中的官方插件；也可输入 `/takeover composer` 等完整命令。查看实际安装的包版本、插件版本、文件、依赖和受影响实例，确认后直接提取，无需配置或调用模型。

已接管插件的源码被手动删除后，可以用同一命令重新提取。目标目录已存在时，会提示目录位置并询问是否覆盖；确认后覆盖同名源码文件，其他文件保留。重新接管会替换同名实现文件中的定制；日常修改可直接编辑已有源码，合并官方更新则使用源码同步。

源码来自当前工程实际安装的 Plugins 包，不会下载最新版。确认期间工程或安装包变化时，需要重新查看计划。接管保留现有参数、组合和布局；若需要准备依赖，会按工程现有包管理器执行，源码写入失败时已准备的依赖可能保留。

升级 npm 依赖会保留本地定制。要把新版官方改动加入已接管的实现，需要另外执行源码同步。

同步时会比较三份代码，保留你的定制并加入官方更新：

| 代码 | 用途 |
| --- | --- |
| 上次采用的官方版本 | 判断此后官方改了什么 |
| 当前本地实现 | 保留项目定制 |
| 已安装的新官方版本 | 提供本次可同步的更新 |

两边改到同一处时，先处理冲突。检查页面和构建后，在更新页确认完成同步。

同步只更新插件实现，组件参数、组合、布局和业务连接会保留。新版接口若有变化，再单独调整调用方式。操作见[源码同步说明](/updates/release-notes#已接管源码的插件)。
