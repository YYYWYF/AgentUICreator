# 源码接管与更新参考

修改文件、组件和本地实现的连贯步骤，统一见[手动修改插件：样式与业务逻辑](./component-customization)。本页用于核对接管后的维护范围。

| 内容 | 默认来源 | 项目如何维护 |
| --- | --- | --- |
| 应用入口、props、组合、业务回调 | 项目 `plugins/<id>/index.tsx` 等 | 普通项目编辑，无需接管；后续保留 |
| 官方实现 | npm 包 | 公开接口不足且用户明确同意后，提取项目实际安装版本 |
| 已接管实现 | 项目插件的 `source/` 目录 | 在适配层修改，原始参考源码与来源记录用于后续同步 |
| 应用布局、Shell、业务服务配置 | 项目文件 | 不属于实现 BASE，不参与官方实现源码合并 |

## 接管与更新边界

首次接管时，Creator 会展示具体插件、当前版本、文件与影响范围，确认后将实现提取到项目。成功接管后，可继续编辑该插件的项目文件；接管其他插件时，再分别确认对应计划。

npm 升级与源码同步是独立步骤。npm 升级不会自动覆盖项目应用层、本地实现或推进 BASE；要采用官方实现改动，另做 BASE／LOCAL／TARGET 合并、验证和明确基线采用。只移植部分特性不表示完成一次源码版本升级。

三方合并会比较三份代码，尽量保留你的修改并加入官方更新：

| 名称 | 比较的是哪份代码 |
| --- | --- |
| BASE | 上一次接管或同步时采用的官方源码，作为比较起点。 |
| LOCAL | 工程中当前的实现，包含你的定制。 |
| TARGET | 工程实际安装的新版 Plugins 包所带的官方源码。 |

两边改到同一处时需要处理冲突。合并后先检查页面和构建，再明确采用新版基线；只升级 npm 或只复制几段新代码，都不会自动完成这一步。

同步只处理插件的实现目录。公共接口发生变化时，单独评估并调整项目中的组件调用；业务连接和 Shell 继续作为项目应用代码维护。具体操作见[更新中心](/updates/)和[源码同步说明](/updates/release-notes#已接管源码的插件)。
