# 同步已接管 Plugin 的实现

当你已把某个官方 Plugin 的实现交给项目维护，升级依赖后可以选择合并它的新变化。没有接管的组件直接使用 npm 实现，不需要这一步。

## 先看三份内容

比较上次采用的官方版本、你当前的定制，以及工程已安装的新官方版本。只选要更新的 Plugin，阅读新增、修改、删除与冲突。不会因为点击检查就自动覆盖文件。

## 合并时保留什么

保留自己的应用层参数、组件组合、页面布局、连接配置和其他 Plugin 定制。本次同步只更新已接管组件的实现文件。若新版参数不兼容，先单独说明要怎样适配，不通过同步偷偷改掉业务代码。

## 操作步骤

1. 更新依赖后打开对应 Plugin 的源码更新。
2. 阅读变化与冲突，选择合并方式；需要时使用模型辅助或手动调整。
3. 审查合并结果，在实际工程运行测试、类型检查和构建。
4. 打开页面检查原定制与新增功能。
5. 确认本次完整更新后，再采用页面提供的新版本记录。

有冲突、检查失败或效果未确认时，不采用新记录，可以保留原版本继续处理。只移植一个修复属于局部定制，不标记为整个版本已更新。

取消源码合并不会撤销已经完成的依赖安装；两步的结果分别查看。首次接管另见[源码接管](../customization/source-takeover)。
