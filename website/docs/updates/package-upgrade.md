# 确认并执行项目依赖升级

当前执行范围是带锁文件的独立 npm/pnpm 工程。先保存已有工作，阅读推荐兼容组合，不通过任意 shell 命令绕过页面确认的升级计划。

## 审查具体计划

确认项目路径、当前与目标精确版本、包管理器、锁文件、必要依赖联动、检查命令和恢复范围。只更新工程实际使用的官方包；Web Component 未使用时不顺带安装。

计划按当前工程和依赖状态生成。生成后又改了文件、版本或升级目标，应重新规划并核对，不能继续执行旧计划。

## 执行与验证

确认后由工具实际安装、更新 lockfile、核对准确产物身份与版本，随后运行相关检查。只改 package.json 不算完成；安装退出码成功也不等于工程验证通过。

保留依赖字段、非目标包与 linked/local/workspace 声明。Host React/UI 库 major 不属于默认联动，必须有单独明确的迁移计划。共享 API 不兼容时阻止或选择兼容目标，不静默重写应用层。

## 完成之后

你的组件应用文件、连接配置、布局和已接管实现应保持保留。默认 npm 实现随包采用，已接管源码可以暂时保持。需要时另外选择源码同步；两阶段分别授权和报告。

失败时查看阶段和恢复信息，保留日志。不要删除锁文件、清空工程或把手动改版本宣称为安装已恢复。
