# 版本与更新

本章用于判断当前环境是否支持升级、查看变化、更新依赖或已接管实现，并在失败时恢复。版本与兼容性说明、项目更新和 Creator 工具更新集中在这里。

## 更新前确认

| 你想确认什么 | 阅读入口 |
| --- | --- |
| 当前项目有哪些可用更新，跨版本改变了什么 | [检查更新与累计变化](./check) |
| 目标平台、框架和包组合是否满足要求 | [兼容性与支持矩阵](./compatibility) |
| 自动更新、源码维护或可选能力有哪些边界 | [支持范围与限制](./limitations) |
| 哪些变化已有正式发布记录 | [正式发布记录](./release-notes) |

从 Creator 设置的「插件更新」进入更新中心，核对当前工程、实际版本、推荐目标和缓存状态。相关包独立版本，推荐组合以审核兼容信息为准。

## 选择更新对象

| 对象 | 操作与保护范围 |
| --- | --- |
| 应用依赖 | [审查并执行依赖升级](./package-upgrade)，检查安装身份和工程验证；保留应用文件、布局和本地实现。 |
| 已接管 Plugin 的实现 | [实现同步](./source-sync)，按原始版本、本地修改和已安装目标合并；与 npm 安装分开确认和采用基线。 |
| Creator 开发工具 | [工具更新](./creator-maintenance)，以实际工具安装目录为目标；自动执行范围按界面和支持说明处理。 |

首次决定是否把官方 Plugin 源码交给项目维护时，先阅读[源码接管](../customization/source-takeover)。依赖升级不会自动授权源码接管或合并。

## 失败后处理

操作未完成时，按[失败恢复](./recovery)区分依赖安装、工程验证和源码阶段。常见错误的定位见[更新与部署排障](../troubleshooting/updates-and-build)。

更新在开发环境操作；发布的应用使用自己的生产依赖和业务服务，不需要连接更新中心。
